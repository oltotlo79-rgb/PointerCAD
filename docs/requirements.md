## 1. プロジェクト概要

### 1.1 目的

座標・数値・数式の入力を第一級の操作としたモデリング(点をプロットし、点を結んで線・面・立体を構成する)と、Blender 風の直感的な 3D 操作感を両立した、履歴パラメトリック方式の 3D CAD を開発する。個人が機械部品の設計から JIS 準拠図面の出力、3D プリント用データの出力までを 1 本で完結できることを目指す。

### 1.2 プロダクト名

**PointerCAD**

### 1.3 ターゲットユーザーと主な用途

- 機械部品設計(切削・板材などの加工に出すことを想定した実部品設計)
- 趣味・DIY・個人利用
- 3D プリント用モデリング

### 1.4 配布形態・ライセンス

- 無料公開の OSS とする
- ライセンス: **Apache-2.0**(利用ライブラリの OpenCASCADE は LGPL-2.1(例外条項付き)であり、動的リンク相当の利用で共存可能)
- 品質目標は「商用製品と同等のクオリティ」(安定性・UX・ドキュメントを含む)

### 1.5 対応プラットフォーム

| 形態 | 対象 |
|---|---|
| デスクトップ | Windows 10/11 (x64)、Linux (x64、AppImage 配布) |
| Web | フル機能 Web 版。Cloudflare Pages 上で配布し、モダンブラウザ(Chrome / Edge / Firefox 最新版)で動作 |

デスクトップ版と Web 版は同一コードベースであり、機能差は原則として設けない(ファイル保存方法などプラットフォーム固有部分のみ差異を許容する)。

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| スケッチ | 点・線分・円弧などの 2D/3D 幾何要素の集合。立体を作るための下書き |
| フィーチャー | 押し出し・穴・面取りなど、形状に対する 1 つの操作単位。履歴ツリーに記録される |
| 履歴パラメトリック | フィーチャーの列としてモデルを保持し、過去のフィーチャーのパラメータ変更で下流を再計算する方式 |
| B-rep | 境界表現。頂点・辺・面でソリッドを表す形状表現。OCCT が採用 |
| 部品(パート) | 単一の部品を表すドキュメント。フィーチャーツリーを 1 本持つ |
| アセンブリ | 複数の部品を配置・拘束して組み合わせたドキュメント |
| 合致拘束 | アセンブリで部品同士の位置関係を定める条件(面合致・軸合致など) |
| 三面図 | 正面図・平面図・側面図。第三角法で配置する |
| 作業平面 | スケッチ入力の基準となる平面(XY/YZ/ZX または任意の面) |
| テッセレーション | B-rep 形状を表示用の三角形メッシュに変換する処理 |
| スプリング | コイルばね。らせん(ヘリックス)に沿って線材の断面を掃引して作る立体 |
| スプライン | 指定した点をなめらかに結ぶ自由曲線。点を全て通す描き方(通過点)と、点で形を引っぱる描き方(制御点)がある |
| 構築線 | 作図の補助専用の線・円。面や立体の材料にはならず、対称の基準や当たりを取るために引く |
| 座標系 | 原点の位置と 3 軸の向きの組。ワールド座標系のほかに、利用者が任意に作るローカル座標系を持てる |
| 抜き勾配 | 型抜きや 3D プリントのために、立体の側面へ付ける傾き(角度) |
| 質量特性 | 体積・質量・重心・慣性モーメントなど、形と材料の密度から求まる性質 |
| 断面図 | 部品を切った切り口を描いた図。内部の形を示すために使う |
| ハッチング | 断面の切り口に入れる等間隔の斜線 |
| 幾何公差 | 形・姿勢・位置・振れの狂いをどこまで許すかの指示(平面度・直角度・位置度など) |
| データム | 幾何公差の基準にする面・軸・点。図面では A・B・C などの記号で示す |
| はめあい | 穴と軸の組合せの緩さ・きつさの決め方。「φ10H7」のような記号で示す |
| 表面性状 | 面の粗さなどの仕上がり具合。図面では Ra・Rz と値を記号で示す |
| 部品表(BOM) | アセンブリに含まれる部品の番号・名称・数量・材質の一覧表 |
| 標準部品 | ボルト・ナット・座金など、規格で寸法が決まっている部品 |
| 外観 | 立体や面の見た目(色・柄・透過率・光沢・粗さ)の設定。形そのものは変えず、フィーチャー履歴とは別に「どこに何を割り当てたか」として保持する |
| 材質プリセット | 鉄板・アルミ・木材・ガラスなど、外観の設定をひとまとめに名前を付けたもの。選ぶだけで色・柄・透過率・光沢・粗さがまとめて決まる |
| 柄(手続き的テクスチャ) | エキスパンドメタル・縞鋼板・木目のように、画像ファイルを持たず計算で描く模様。模様の大きさを数値で指定できる |

## 3. コンセプトと全体像

1. **座標・数式ファースト**: すべての数値入力欄で数式(√・分数・π・累乗・四則演算)が使える。点のプロット→接続という明示的な作図を操作の基本とする。
2. **Blender 風の操作感**: ビューポート操作(オービット/パン/ズーム)、ショートカット体系、画面レイアウトの感覚を Blender を基準に設計する。
3. **Inventor 風の履歴パラメトリック**: 操作はフィーチャーツリーに記録され、後からパラメータを編集すると下流が再計算される。部品→アセンブリ→図面という文書構成も Inventor に倣う。
4. **説明なしで使える UX**: 初見でもツールチップ・ステータスバーのガイド・妥当なデフォルト値だけで操作が完結することを非機能要件の柱とする。

ドキュメントの流れ:

```
スケッチ(点・線・円弧・面)
   ↓ フィーチャー(押し出し/回転/縫合/穴/面取り…)
部品(パート) ── 色・材質(外観)
   ↓ 配置・合致拘束
アセンブリ
   ↓ 三面図自動生成・寸法
図面(A3/A4) → PDF / JPEG
部品・アセンブリ → STEP / STL / 3MF / OBJ / glTF
```

## 4. 機能要件

要件 ID の凡例: `FR-カテゴリ番号-連番`。優先度は MoSCoW(Must / Should / Could)で表す。

| FR-102 | 透視投影/平行投影の切り替え | Must |

|---|---|---|
| FR-301 | **点のプロット(絶対座標)**: X, Y, Z を数式込みで指定して点を作成 | Must |
| FR-302 | **点のプロット(相対座標)**: 直前の点、または任意に選択した既存の点を基準に、シフト量(ΔX, ΔY, ΔZ)を指定して点を作成 | Must |
| FR-303 | 点のプロット(極座標): 基準点+方向(角度)+距離で点を作成 | Must |
| FR-304 | **線分**: 2 点間を結ぶ。または始点+方向・長さ・角度指定で作成 | Must |
| FR-305 | **円弧**: 中心点+半径+開始角度+終了角度で作成(作業平面上)。全周指定で円になる | Must |
| FR-306 | 3 点円弧(始点・終点・通過点)による作成 | Should |
| FR-307 | **連続描画**: 線・円弧の端点から続けて次の線・円弧を描ける(端点スナップ+チェーン入力モード) | Must |
| FR-308 | **点列生成**: 基準点+方向+間隔+個数を指定して、一直線上に等間隔の複数点を一括作成 | Must |
| FR-309 | **面の作成**: 同一平面上の閉ループ(線・円弧の連なり、または点列の順次接続)から面を作成。点のみを順に選んで面を張ることもできる(隣接点間に線が自動生成される) | Must |

| FR-317 | **スプライン**: 指定した点を全て通る曲線(通過点)と、点で形を引っぱる曲線(制御点)の 2 通りで滑らかな曲線を描ける。点は後から追加・移動・削除でき、各点の座標は数式で指定できる | Must |

| FR-319 | 文字の輪郭化: 文字列・書体・文字高さを指定して、文字の輪郭をスケッチ要素として配置できる(刻印・銘板の下描き用) | Should |

### 5.1 UX(最重要非機能要件)

**「説明を読まなくても直感的に操作できる」** を UI 設計の最上位原則とする。

| ID | 要件 |
|---|---|
| NFR-UX-1 | 操作文法の一貫性: 「対象を選んでから操作」「操作を選んでから対象」のどちらの順でも成立させる |
| NFR-UX-2 | 直接操作優先: 数値入力はモーダルダイアログではなく、ビューポート内のその場に浮かぶ入力欄で行う(Blender 的操作感) |
| NFR-UX-3 | すべての操作が Undo 可能であること。確認ダイアログは復元不能な操作(ファイル上書き等)に限る |
| NFR-UX-4 | 全パラメータに妥当なデフォルト値を設定し、Enter 連打だけでも意味のある結果になる |
| NFR-UX-5 | エラーの事前防止: 無効な値は実行前に赤表示+理由提示。実行してから失敗させない |
| NFR-UX-6 | 空状態ガイド: 新規ドキュメントでは「最初の一歩」(点のプロット/スケッチ開始)を画面上で提示する |
| NFR-UX-7 | 操作ガイド(FR-904/905 のツールチップ・ステータスバー)を全ツールで欠かさない |

### 5.2 性能

想定規模: 1 部品あたり〜200 フィーチャー、アセンブリ〜50 部品を実用範囲とする。

| ID | 要件 |
|---|---|
| NFR-PF-1 | ビューポート操作(オービット/パン/ズーム)は上記規模で 60fps(最低 30fps)を維持 |
| NFR-PF-2 | 単一フィーチャーの適用・プレビュー更新は典型形状で 500ms 以内 |
| NFR-PF-3 | 100 フィーチャー部品の全再計算は 5 秒以内(未変更フィーチャーの結果キャッシュで短縮する) |
| NFR-PF-4 | 幾何カーネルは Web Worker 上で実行し、計算中も UI がフリーズしない(進捗表示+キャンセル可能) |
| NFR-PF-5 | 起動時間: デスクトップ 5 秒以内、Web 版初回ロード 10 秒以内(通常回線)・2 回目以降 3 秒以内 |
| NFR-PF-6 | メモリ: WASM の実質上限(〜4GB)内で動作。上限接近時に警告する |

### 5.3 信頼性・精度

| ID | 要件 |
|---|---|
| NFR-RE-1 | モデリング操作の失敗(フィレット不成立等)でアプリケーションがクラッシュしない。失敗理由をユーザーに提示する |
| NFR-RE-2 | 自動保存とクラッシュ復元(FR-805) |
| NFR-RE-3 | 内部単位は mm、幾何公差は OCCT 既定(1e-7)を基準とする |
| NFR-RE-4 | 式評価は任意精度で行い、丸めは最終段のみ(FR-203) |

### 5.4 セキュリティ・プライバシー

| ID | 要件 |
|---|---|
| NFR-SE-1 | テレメトリ・外部送信は一切行わない。Web 版も静的配信のみでモデルデータはブラウザ外に出ない |
| NFR-SE-2 | 依存ライブラリは Dependabot 等で脆弱性監視する |

### 5.5 保守性・開発プロセス

| ID | 要件 |
|---|---|
| NFR-MA-1 | モノレポ構成でパッケージ境界を明確化(§6.2)。UI から幾何カーネルへ直接依存しない(ドキュメントモデル経由) |
| NFR-MA-2 | テスト: 式エンジン・ドキュメントモデル・フィーチャー再計算はユニットテスト必須(TDD)。主要ユーザーフローは E2E テスト(Playwright)。カーネル演算は Node 上でヘッドレス実行して検証 |

## 6. システム構成・技術スタック

### 6.1 技術選定

| レイヤ | 採用技術 | 選定理由 |
|---|---|---|
| 言語 | TypeScript(strict) | Web/デスクトップ同一コード、型安全、情報量最多 |
| 幾何カーネル | OpenCASCADE (OCCT) の WASM ビルド(opencascade.js。必要に応じ Emscripten 自前ビルド) | 商用実績のある B-rep カーネル。ブーリアン・フィレット・STEP を自作せずに済む |
| 3D 描画 | Three.js(WebGL2) | カスタム CAD UI(ビューキューブ・スナップ表示等)の作り込みに最適 |
| UI フレームワーク | React + Zustand(状態管理) | コンポーネント資産・情報量 |
| 式エンジン | 自作パーサー + decimal.js(任意精度評価) | √・n乗根・分数・π・累乗の要件を満たす最小構成 |
| デスクトップ | Electron(Windows: NSIS インストーラ / Linux: AppImage) | Web 版とのレンダリング一致・配布容易性 |
| Web 配信 | Cloudflare Pages(静的配信、COOP/COEP ヘッダー設定) | 要件指定。サーバーレスで運用費ゼロ |
| 図面 → PDF | SVG で描画し、ベクター PDF 化(jsPDF + svg2pdf.js 等)。JPEG/PNG は Canvas ラスタライズ | 図面のベクター品質を保つ |
| カーネル実行 | Web Worker + Comlink | UI スレッド非ブロッキング(NFR-PF-4) |
| ビルド | Vite + pnpm workspaces(モノレポ) | 高速な開発サイクル |
| テスト | Vitest(ユニット)+ Playwright(E2E) | NFR-MA-2 |
| CI/CD | GitHub Actions | lint / test / build / リリース(electron-builder)/ Pages デプロイ |

バージョン方針: 依存はすべて lockfile で固定し、opencascade.js は特定バージョンにピン止めして更新は検証付きで行う。

### 6.2 パッケージ構成(モノレポ)

```
pointercad/
├── packages/
│   ├── expression/      # 式パーサー・任意精度評価(依存なしの純粋ロジック)
│   ├── kernel/          # OCCT WASM ラッパー(形状生成・ブーリアン・面取り・テッセレーション・STEP/STL 変換)
│   ├── model/           # ドキュメントモデル: フィーチャー履歴・部品・アセンブリ・再計算エンジン・Undo
│   ├── drawing/         # 図面生成: 投影(HLR)・寸法・JIS スタイル・SVG 生成
│   ├── io/              # .pcad 形式、STEP/STL/3MF/OBJ/glTF 入出力、PDF/JPEG 出力
│   ├── ui/              # React コンポーネント群: ビューポート・ビューキューブ・ツリー・入力欄・ヘルプ
│   └── help-content/    # ヘルプ文書(Markdown)
├── apps/
│   ├── desktop/         # Electron シェル
│   └── web/             # Web 版エントリ(Cloudflare Pages)
└── docs/                # 本書・設計文書
```

依存方向は `apps → ui → model → kernel/expression` の一方向とし、逆流を禁止する。

### 6.3 データフロー

```
ユーザー操作(UI)
  → コマンド発行(Undo 履歴に記録)
  → ドキュメントモデル更新(フィーチャー追加/編集)
  → 再計算エンジン(変更以降のフィーチャーのみ。結果キャッシュ)
  → kernel(Web Worker 内の OCCT)で B-rep 生成
  → テッセレーション → Three.js シーン更新
```

## 10. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| opencascade.js のメンテ停滞・バージョン遅れ | カーネル更新不能 | Emscripten による OCCT 自前 WASM ビルド手順を早期(P0)に確立し、逃げ道を確保 |

## 11. スコープ外(明示的にやらないこと)

- **自由曲面モデラー**(制御点をつまんで曲面を作り込む、曲率連続を制御するなどのサーフェスデザイン)。ただし**限定利用の曲面**(押し出し面・回転面・オフセット面・縫合・延長・トリム・厚み付け)は FR-428 として P5 で扱う
- 板金展開、CAM、CAE/FEM 解析
- フォトリアルレンダリング(大域照明・レイトレーシング・現実の光源の再現)。**見た目の色・材質・柄は FR-1106〜1110 として P5 で扱う**(v1.2。v1.1 では FR-1103 として P10 に置いていた)
- クラウド保存・アカウント機能・複数人同時編集
- 2D 専用 CAD としての本格製図(あくまで 3D モデルからの図面生成が主)
- DWG 出力(DXF で代替する)
- 可動拘束(FR-608)は将来検討

**v1.1 で対象内へ変更したもの**(v1.0 では「将来検討」または未記載だったもの)

| 項目 | v1.0 の扱い | v1.1 の扱い |
|---|---|---|
| 曲面 | 「サーフェスモデリング(自由曲面デザイン)」として一括で対象外 | 限定利用(押し出し面・回転面・オフセット面・縫合・延長・トリム・厚み付け)を FR-428 として P5(Should)。自由曲面モデラーは対象外のまま |
| 断面図・詳細図 | FR-712「将来」 | 対象内。断面図を FR-713(Must)、部分拡大図・破断図・部分投影図を FR-714(Should)として P8 |
| 幾何拘束・寸法拘束 | FR-313「将来」 | 対象内。P4(スケッチ拡張)の Should。座標・数式による指定を主とし、拘束は式に加えて使える位置づけ |
| DXF | FR-808「将来」 | 対象内。図面の DXF 出力を P8、DXF の読み込み(FR-809)を P6 |
| 溶接記号 | 記載なし | 対象内。FR-727 として P9(Could) |

FR-313・FR-712・FR-808 の各行の文言は v1.0 のまま残してあり、扱いの変更はこの表と §9 を正とする。
