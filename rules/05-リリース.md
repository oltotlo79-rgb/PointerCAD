# 11. リリース

## 11.1 リリース時に必ず最新化するもの

- **リリースのたびに、ヘルプを最新の状態にする。** 実装した機能がヘルプ(FR-901)に載っていない状態でリリースしない。
- **画像も対象**: 画面の見た目が変わる変更(区画の広さ、配色、表示の追加など)が入ったら、ヘルプ内の既存スクリーンショットは全て古くなる。撮り直す。
- **取扱説明書も最新化する(v1.9、FR-910)**: 取扱説明書はヘルプ(FR-901)のMarkdownから生成する。ヘルプを更新したら取扱説明書を生成し直し、スクリーンショットも撮影台本から撮り直す。生成した説明書とヘルプが整合していること(NFR-MA-6)を確認するまでリリースしない。
- **全機能を実画面で詳説する(2026-09-09の利用者指示)**: 取扱説明書は全機能の入口・前提・入力・操作手順・結果を実際のアプリ画面で解説する。ページ数が多い場合は機能別に分冊してよい。分冊しても共通の目次から全巻・全機能へ辿れるようにし、ヘルプのトピックIDと説明書の章IDの対応を維持する。本文を別々に編集せず同じヘルプMarkdownから生成し、文言・画像・対象バージョンの一致と、重複・欠落・リンク切れがないことをリリース前の整合検査で確認する。配布・同梱する説明書には全巻を含める。
- **利用者向けREADMEを最新化する(2026-09-09の利用者指示)**: 特徴・強み・実際にできることに加え、他のCADとの違い・差別化ポイントと利用者のメリットを明確に記載する。他製品との比較は公式資料を根拠にし、他製品にもある機能を独自機能と称さない。正式リリースでは`README.md`の`pointercad:release-links`区間を、Windowsインストーラー・Linux AppImageのダウンロード、取扱説明書(HTML/PDF)、Webアプリ版の実在する公開リンクへ更新する。未公開の案内・仮URL・リンク切れを残したまま公開完了としない。配布物・説明書・Web版の版を対応させ、各リンクから実際に取得・閲覧・起動できることを確認する。
- **計画・方針変更時にもREADMEを見直す(2026-09-11の利用者指示)**: 新しい計画、機能追加、方針変更が特徴・強み・差別化・できること・参照資料へ影響する場合は、その変更と同じまとまりでREADMEを更新する。計画中の機能は利用可能と書かず、実装した時点で説明とヘルプへの導線を更新する。見直した箇所と反映結果を報告記録へ残す。
- **バージョン番号の一致**: ルート `package.json`、`apps/desktop`・`apps/web` の `package.json`、electron-builderの設定、gitタグでバージョンを一致させる。

## 11.2 リリース手順の順序

機能凍結 → ヘルプ・画像の更新 → **撮影(撮影台本によるスクリーンショットの自動生成)→ 取扱説明書の生成(ヘルプのMarkdownから章を作る)→ 整合検査(`check-release-ready.ps1`。ヘルプと取扱説明書の1対1対応・文言一致・画像の生成元一致・機能の過不足なし。NFR-MA-6)** → `scripts/check.ps1` 合格 → リリースノート(日本語)作成 → コミット → タグ → デスクトップ成果物(Windows: NSIS / Linux: AppImage。**取扱説明書(PDF)を同梱**)の生成と起動確認 → Web版(Cloudflare Pages。**取扱説明書を同梱**)のデプロイ確認

- バージョン一致・ヘルプ鮮度・**ヘルプと取扱説明書の整合(NFR-MA-6)**を自動検査する `scripts/check-release-ready.ps1` はP13までに実装する(`rules/00-施行の仕組み.md` 参照)。実装までは上記を手動チェックリストとして1項目ずつ確認し、結果を `docs/報告記録.md` へ記録する。
- 同スクリプトにはREADMEの公開リンクの必須種類・未公開案内の残存・配布対象版の一致も含める。公開先でのダウンロード・説明書閲覧・Web起動は公開先の検証で確認し、その結果を記録する。READMEの更新は正式公開の完了条件に含む。

## 11.3 解説に載せる範囲

- **利用者の操作と画面表示に関することだけを載せる。** 内部の計算方式、データ構造、最適化、アルゴリズム名は載せない。
- 判断基準: 「利用者が画面で見る」「利用者が操作する」もののみ。利用者が知らなくても使えることは書かない。
- 内部用語(B-rep、テッセレーション、ソルバー、Worker等)を利用者向けの文章に出さない。
- 理由: ヘルプは操作の手引きであり、設計文書ではないため。

## 11.4 READMEの実画面・操作動画(2026-09-09の利用者指示)

- **可能な範囲で実画像と操作動画を掲載する。利用者が正式リリース後の掲載も許可している。** READMEの紹介用メディアは公開後に追加してよい。§11.1の全機能を説明するヘルプ・取扱説明書の画像を後回しにする許可とは扱わない。
- **撮影対象**: ①座標・相対座標の入力から作図、②日本語のパラメータの変更に形が追従する前後、③部品の組み立て・ジョイント操作・干渉確認。READMEの強みの説明と対応させ、撮影台本・使用サンプル・撮影したリリース版を記録する。説明書と同じ操作は同じ台本・画像を再利用する。
- **掲載方法**: READMEの`pointercad:demo-media`区間に、実画面のスクリーンショットと説明・代替テキストを置く。動画が用意できた場合は30〜60秒程度を目安に、内容の分かるサムネイルから実在する動画へリンクする。動画内の操作は字幕や入力値で追えるようにする。
- **公開前の確認**: 配布対象版のアプリを実際に操作して撮影した素材を使い、画面の文字と形状が読めること、掲載版・ヘルプの操作・映像が一致すること、READMEの表示と動画の再生リンクが有効なことを確認する。仮画像・存在しない画像パス・生成した架空のアプリ画面を掲載しない。
- **記録**: 各リリースのREADME確認で、掲載済みの素材と版、未掲載の場合は理由と次の対応を`docs/報告記録.md`に残す。紹介メディアの追加だけで原計画の実装完了数を増やさない。
