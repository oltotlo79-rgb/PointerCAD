## 2. 技術方式

### 2.1 規格と14種類

入手済み資料、確認範囲と本文照合の状態は[規格資料の索引](P9-規格資料索引.md)へ記録する。必要資料は実装担当が用意し、利用者の資料提供を前提にしない。

| 群 | 種類 | 要件上の優先度 |
|---|---|---|
| 形状 | 真直度、平面度、真円度、円筒度 | 平面度Must、残りShould |
| 輪郭 | 線の輪郭度、面の輪郭度 | Should |
| 姿勢 | 平行度、直角度、傾斜度 | 前2つMust、傾斜度Should |
| 位置 | 位置度、同軸度、対称度 | 前2つMust、対称度Should |
| 振れ | 円周振れ、全振れ | 円周振れMust、全振れShould |

採用対象の番号・年の根拠は [JIS B 0021:1998](https://webdesk.jsa.or.jp/books/W11M0090/index/?bunsyo_id=JIS+B+0021%3A1998)、データムは [B 0022:1984](https://webdesk.jsa.or.jp/books/W11M0090/index/?bunsyo_id=JIS+B+0022%3A1984)、実体公差方式は [B 0023:1996](https://webdesk.jsa.or.jp/books/W11M0090/index/?bunsyo_id=JIS+B+0023%3A1996)。溶接は [JIS Z 3021:2016](https://webdesk.jsa.or.jp/books/W11M0090/index/?bunsyo_id=JIS+Z+3021%3A2016) のSystem Bを対象にする（2026-09-10確認）。ISO/ASMEの別の版の例を混ぜない。

### 2.2 意味と参照

`DatumId / ToleranceCharacteristic / ToleranceZone / FrameSegment[] / DatumReference[]`を判別共用体で表す。値は式のsourceと単位、記号は列挙型、データムは安定IDで保存する。表示名Aの改名で参照を切らない。対象にはsourceRef、viewId、occurrenceId、元形状への参照を持ち、単なる画面座標から面や軸を推測し直さない。

2026-09-10の実装接続: 文書全体の型が既に葉のdrawingに置かれているため、共有する記録型は`drawing/gdt/types.ts`に置く。modelはこの型を公開し、参照・式・規格条件・操作を実装する。保存された導出値を信用せず、対象と式から毎回解決する。寸法公差の単位はmm/inchを式と組にして保持し、表示設定の変更だけでは物理的な許容値を変えない。

形状公差にデータムが不要な場合、姿勢・振れ等で必要な場合、実体記号の使用できる対象を規格照合表で判定する。輪郭度・位置度を一律に「必ずデータム3個」としない。重複データム、自己参照、存在しないID、負値、単位不一致を理由付きで扱う。複数行は各段の意味を保持し、単に文字列を改行して複合公差と呼ばない。条項で成立しない組合せは入力時に説明する。

### 2.3 紙上の形と操作

文字高の初期値3.5mm、線幅0.25mm、左右の最小余白1mmは製品の初期値でありJIS規定値と称さない。文字の実アウトライン境界で枠幅を計算し、最大3段のデータム欄を順序付きに配置する。14記号・直径・囲みM・データム三角をvectorで作り、文字だけ同梱字体を使う。基本寸法は既存寸法の表示種別を追加し、計算値や寸法線の参照は共有する。

「データム」→対象→名前→配置、「幾何公差」→対象→種類/値/基準→配置の順と先選択の両方を支える。ドラッグは紙上位置だけ変え、Escで戻る。失われた参照は警告と再選択の入口を残す。未解決の公差を正常な製作指示として書き出さず、該当IDと理由を出力時にも示す。

### 2.4 溶接と出力

System Bの矢側/反対側/両側を保存し、すみ肉、I/V/X/レ/U/J形の開先、スポット/シームの基本記号とサイズ・長さ・ピッチ、全周・現場・仕上げ・尾部注記を対象にする。該当しないサイズ欄は無効理由を示す。標準の記号形状と寸法位置はタスク14の照合表を正とし、文字記号の自由入力で代用しない。

画面、PDF、SVG、PNG/JPEG、DXF、印刷は同じ描画要素を消費する。DXFは相手CADの専用GD&Tオブジェクトを必要としない線・円弧・文字アウトラインへ変換する。意味を保つ再編集は.pcaddが担当する。テーマや紙倍率を変えても記入枠の紙上寸法は一定。

### 2.5 数値付きの代表例

平面度0.05（データムなし）、直角度0.02/A、位置度直径0.1＋囲みM/A/B/Cの3図を最初の受入にする。14種すべての合法例、負の値・不足参照等の不合法例を別フィクスチャで持つ。紙上寸法誤差0.01mm以内、保存往復のAST完全一致、100回の注記移動でカーネル再計算0回を合格条件にする。0.01mmは本製品の描画検査許容差であり実物の加工精度ではない。

## 4. 共通の作業規約

- 最新の利用者指示により、実装・調査・資料作成は本エージェントが直接行う。**サブエージェントは使用しない**。旧計画のモデル名や委譲表を適用しない。
- 文書変更は不可変の定義に適用し、確定1操作をUndo 1回で戻す。一時プレビュー、検索、カメラ移動は文書に保存しない。端末設定は文書のUndoと分け、取消・既定値復元を備える。
- 式は文字列で保存し、任意精度で評価してカーネル境界でdoubleへ変換する。幾何許容誤差はmmと明示した値で判定する。UIからカーネルを直接呼ばない。
- 新規・切替・閉じる・保存先変更と非同期処理の競合では、文書IDと世代を照合し、旧結果で新文書や保存済み状態を更新しない。失敗時に唯一の控えを消さない。
- UIの追加には既存5区画、その場の入力、先選択/後選択、Enter/Esc、空状態、理由付きエラー、F1、ツールチップ、ステータス、翻訳キーを揃える。ヘルプ本文と説明書の章は同じMarkdownから供給する。
- 診断と必須ゲートを混同しない。検査は `scripts/check.ps1` のみを入口とし、検査中にソース・文書・indexを変更しない。未実在のテストを指定して「成功」と扱わない。
- コミットは§タスク一覧の**原計画IDを10件以上**、機能として区切りのよい範囲でまとめ、mainへ着地させる。ファイル数、検査数、不具合修正数を追加タスクに数えない。
- 完了は実装・保存・Undo・画面/出力・ヘルプ・必要な検査の全成立後。報告記録に成果物、残件、完成度、コミットまであと何分かの見積もりと根拠を書く。

- WebとDesktopで、平面度・直角度・位置度の代表3枠、14種一覧、基本寸法、最大実体、溶接を作成し、保存→再開→上流変更→再選択→Undo→出力まで通す。

- 実際の図示が規格照合表と一致したことを記録し、規格番号の確認だけで「準拠確認済み」と表示しない。

### 5.1 検査・記録

1. §タスク一覧の合格条件を実データで確認し、数値・画像・出力ファイル・実行ログを保存する。診断で失敗した場合は原因箇所を直し、影響範囲の検査から再開する。
2. 変更が揃ってから手動の全5段検査 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check.ps1` を実行する。通常コミット前4段・通常push前5段も省略しない。
3. mainのローカルSHA、リモートSHA、同一SHAのCI結果を区別して記録する。実装済みでも未検証・未送信のものを確定完成度へ足さない。
4. 最終公開はP13のリリース前検査・配布物確認まで必要。本フェーズの合格だけで製品完成とは報告しない。
