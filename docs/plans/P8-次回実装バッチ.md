## 着手前に潰す不一致

1. **はめあいの種類数。** `fits-jis-b-0401.json`は13寸法区分・14種類（H6/H7/H8/H9/e8/f7/g6/h6/h7/js6/k6/m6/n6/p6）。計画とJSONの説明の「15」は列挙された名前の個数と一致しない。存在しない15番目を創作せず、元の列挙と件数を照合して記述を訂正する。
2. **規格値の確認状態。** 0〜3、6〜10、180〜250mmのp6と、250〜500mmの全種類には確認不足が記録されている。IT12も未取得。メーカー等の独立した一次資料で不足を調べ、取得できた数値と出典を記録する。未確認値を確認済みへ変えたり、欠損を0で埋めたりしない。1〜500mmという承認済み範囲を都合で狭めない。
3. **大文字小文字を保持する。** はめあい表は`ES`/`es`、`H7`/`h7`が別の意味を持つ。Windows PowerShell 5.1の`ConvertFrom-Json`はこの表の列定義を重複キーとして拒否することを実測した。表の集計・生成は大文字小文字を区別するJSON処理を使い、列数・キー名・単位を導入時の回帰検査へ固定する。
4. **字体は未導入。** 追跡対象にttf/otfはなく、drawingの依存に`opentype.js`もない。P8 §0.a-0.10/0.11の承認済み方式で導入し、同じ字体をWebとdesktopに配る。取得元・版・hash・ライセンスを保存し、lockfileも同時更新する。導入手順はパッケージ操作と検査の規約に従う。
5. **記号の旧期待値。** タスク32の第三角法記号の線・円弧の本数と、タスク9で作った記号の表現が異なる。共通化時に見た目と投影法の意味から照合し、テストに合わせて記号を変形させない。確認できていない寸法は規格値と断定しない。

## まとめて確認する操作と回帰条件

- 長さ50の斜辺を長さ30に投影しても、実距離寸法は50。水平・垂直・座標寸法は指定した図の基底成分を使う。縮尺を変えても測定値は変えない。
- 同じ部品を異なる配置で置いたアセンブリでも対象を取り違えない。投影の由来が曖昧なら未解決として残し、数値の代わりに`？`と件数を表示する。
- 「対象→種類」と「種類→対象」が同じ寸法を作る。Enterで既定の種類を確定し、作った寸法を選択する。
- 寸法のドラッグはマウスを離した時だけ履歴を1段追加する。Undo/Redoで文書・選択・表示が整合する。寸法値そのものの手入力欄を作らない。
- はめあい表は寸法区分の境界、大文字小文字、µm→mm、上下限の大小、未知の記号、欠損値を確認する。
- 「8」「φ」「日」「板」の輪郭と内部の穴を維持する。未読込・欠字・読込失敗を区別し、文字幅は実際の字体から測る。
- 中心マークの削除が再計算で復活しない。自動寸法の再実行で手動寸法を消さず、同じ入力から同じ順序・同じ個数を得る。
- 元の板厚3→5で寸法も5へ更新する。穴の削除でその寸法を未解決として残し、変更していない図の投影キャッシュを再利用する。
- 画面とSVGは同じ図面表現を使い、非表示・印刷対象外レイヤーを混同しない。
