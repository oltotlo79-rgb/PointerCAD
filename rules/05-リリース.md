# 11. リリース

## 11.1 リリース時に必ず最新化するもの

- **リリースのたびに、ヘルプを最新の状態にする。** 実装した機能がヘルプ(FR-901)に載っていない状態でリリースしない。
- **画像も対象**: 画面の見た目が変わる変更(区画の広さ、配色、表示の追加など)が入ったら、ヘルプ内の既存スクリーンショットは全て古くなる。撮り直す。
- **バージョン番号の一致**: ルート `package.json`、`apps/desktop`・`apps/web` の `package.json`、electron-builderの設定、gitタグでバージョンを一致させる。

## 11.2 リリース手順の順序

機能凍結 → ヘルプ・画像の更新 → `scripts/check.ps1` 合格 → リリースノート(日本語)作成 → コミット → タグ → デスクトップ成果物(Windows: NSIS / Linux: AppImage)の生成と起動確認 → Web版(Cloudflare Pages)のデプロイ確認

- バージョン一致・ヘルプ鮮度を自動検査する `scripts/check-release-ready.ps1` はP13までに実装する(`rules/00-施行の仕組み.md` 参照)。実装までは上記を手動チェックリストとして1項目ずつ確認し、結果を `docs/報告記録.md` へ記録する。

## 11.3 解説に載せる範囲

- **利用者の操作と画面表示に関することだけを載せる。** 内部の計算方式、データ構造、最適化、アルゴリズム名は載せない。
- 判断基準: 「利用者が画面で見る」「利用者が操作する」もののみ。利用者が知らなくても使えることは書かない。
- 内部用語(B-rep、テッセレーション、ソルバー、Worker等)を利用者向けの文章に出さない。
- 理由: ヘルプは操作の手引きであり、設計文書ではないため。
