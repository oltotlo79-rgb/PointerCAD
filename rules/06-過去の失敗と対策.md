# 10. 過去の失敗と対策

## 記録の義務

- 不具合、手戻り、規約違反、検査のすり抜けが起きたら、**同日中に**本書へ追記する。
- 対策は可能な限り**仕組み**(フック・検査スクリプト・CI)へ落とし込み、`rules/00-施行の仕組み.md` の表へ反映する。「気をつける」だけの対策を認めない。
- 指示書(`rules/01-役割と委譲.md` §3)には、関係する本書の項目を必ず引用する。

## 記録の様式

各項目は次の4点を必ず含める。

```markdown
## 10.N 見出し(YYYY-MM-DD)

- **起きたこと**: 観測された事実。実測値・エラーメッセージ・ファイルパスを実名で書く。
- **原因**: 確かめた原因。推測は「推測」と明記し、断定しない。
- **仕組みでの対策**: 追加・変更したフック/スクリプト/検査の実名と、何を防ぐか。
- **確認方法**: 対策が働いていることを確かめるコマンドまたは手順。
```

## 記録

## 10.1 規約フックが作業担当(サブエージェント)の pnpm 実行まで拒否した(2026-09-02)

- **起きたこと**: `.claude/hooks/block-direct-package-managers.ps1` が、統括だけでなく Agent ツールで起動した作業担当(サブエージェント)の PowerShell / Bash ツールからの `pnpm --version` も拒否した(2026-09-02 実測。拒否メッセージ「規約(rules/01-役割と委譲.md §1、rules/02-禁止事項.md)により、統括は pnpm / npm / npx / yarn を直接実行できません」)。P0 の足場作り(`pnpm install`)を作業担当が実行できない状態だった。
- **原因**: 前作 ORIGAMI3 では作業担当が Codex(別プロセス)で Claude Code のフックが及ばなかったが、本プロジェクトは作業担当も同一セッション内の Claude サブエージェントであり、`.claude/settings.json` のフックが作業担当のツール呼出にも適用される。フック設計時にこの差を考慮していなかった(実測で確認済み)。
- **仕組みでの対策**: フックに「入力 JSON の `agent_id`(サブエージェント発の呼出にだけ付く識別子)が存在し空でなければ通す」判定を追加した。無い・空文字・null・空白だけの場合は従来どおり拒否する(統括への拒否は弱めない)。自己試験 `block-direct-package-managers.test.ps1` へ6件追加(非空→通す×2、無し/空文字/null/空白→拒否×4)。`rules/00-施行の仕組み.md` の施行表へ判別方法を追記した。
- **確認方法**: `powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .claude/hooks/block-direct-package-managers.test.ps1` が32件全て合格すること。作業担当から `pnpm --version` がバージョン(実測 11.2.2)を返し、統括からは従来どおり拒否されること。

前作にあたるORIGAMI3の失敗集(`ORIGAMI3/docs/rules/06-過去の失敗と対策.md`)のうち、本プロジェクトの規約へ先回りで取り込んだ教訓は次のとおり。

- 実装者の自己申告だけで合格にしない → 統括による再検査(`rules/03-品質ゲート.md` §7)
- 検査コマンドをCIと手元で二重管理して食い違う → 検査の単一正本化(`scripts/check.ps1`、§7.2)
- テストが追跡ファイルを書き換えて作業ツリーが汚れる → 検査前後のgit status比較(§7.1 #0)
- 実在しないファイル名・関数名で指示して無効な作業をさせる → 指示書の実在確認(`rules/01-役割と委譲.md` §3-1)
- 期待値の緩和・警告の抑止で赤を消す → 禁止事項(`rules/02-禁止事項.md`)
