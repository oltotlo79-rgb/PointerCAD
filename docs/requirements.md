## 1. プロジェクト概要

### 1.1 目的

座標・数値・数式の入力を第一級の操作としたモデリング(点をプロットし、点を結んで線・面・立体を構成する)と、Blender 風の直感的な 3D 操作感を両立した、履歴パラメトリック方式の 3D CAD を開発する。個人が機械部品の設計から JIS 準拠図面の出力、3D プリント用データの出力までを 1 本で完結できることを目指す。

### 1.2 プロダクト名

**PointerCAD**

### 1.3 ターゲットユーザーと主な用途

- 機械部品設計(切削・板材などの加工に出すことを想定した実部品設計)
- 趣味・DIY・個人利用
- 3D プリント用モデリング

### 1.4 配布形態・ライセンス

- 無料公開の OSS とする
- ライセンス: **Apache-2.0**(利用ライブラリの OpenCASCADE は LGPL-2.1(例外条項付き)であり、動的リンク相当の利用で共存可能)
- 品質目標は「商用製品と同等のクオリティ」(安定性・UX・ドキュメントを含む)

### 1.5 対応プラットフォーム

| 形態 | 対象 |
|---|---|
| デスクトップ | Windows 10/11 (x64)、Linux (x64、AppImage 配布) |
| Web | フル機能 Web 版。Cloudflare Pages 上で配布し、モダンブラウザ(Chrome / Edge / Firefox 最新版)で動作 |

デスクトップ版と Web 版は同一コードベースであり、機能差は原則として設けない(ファイル保存方法などプラットフォーム固有部分のみ差異を許容する)。

| データム | 幾何公差の基準にする面・軸・点。図面では A・B・C などの記号で示す |
| はめあい | 穴と軸の組合せの緩さ・きつさの決め方。「φ10H7」のような記号で示す |
| 表面性状 | 面の粗さなどの仕上がり具合。図面では Ra・Rz と値を記号で示す |
| 部品表(BOM) | アセンブリに含まれる部品の番号・名称・数量・材質の一覧表 |

| 切断面 | 立体を切断するために指定する平面。点・辺・軸・既存の面・作業平面の組み合わせで決める |
| 残す側 | 切断で 2 つに分かれた立体のうち、削除せずに残すと選んだ側 |
| 拘束 | スケッチの要素に付ける条件。長さ・角度・半径などの数値で決める寸法拘束と、平行・垂直・接線・同心・等しい・一致・水平・垂直・対称のように形どうしの関係で決める幾何拘束がある |
| パラメータ | 名前を付けた数値(板厚・穴径など)。式から名前で参照でき、値を変えると参照しているところが全て追従する |
| 直接編集 | 履歴をたどらずに、立体の面をそのまま押し引き・移動して形を直す操作 |
| 板金 | 一定の板厚の板を曲げて作る部品。曲げの半径を決めて折り曲げ、平らに伸ばした形を出して板から切り出す |
| フランジ | 板金の部品で、縁を折り曲げて立ち上げた部分 |
| 展開図 | 板金の部品の曲げを全て伸ばして平らにした形。板取り・切り出しに使う |
| レイヤー | 要素を分類して束ねる入れ物。束ごとに表示の入切・線種・色・線幅をまとめて決められる |

## 3. コンセプトと全体像

1. **座標・数式ファースト**: すべての数値入力欄で数式(√・分数・π・累乗・四則演算)が使える。点のプロット→接続という明示的な作図を操作の基本とする。
2. **Blender 風の操作感**: ビューポート操作(オービット/パン/ズーム)、ショートカット体系、画面レイアウトの感覚を Blender を基準に設計する。
3. **Inventor 風の履歴パラメトリック**: 操作はフィーチャーツリーに記録され、後からパラメータを編集すると下流が再計算される。部品→アセンブリ→図面という文書構成も Inventor に倣う。
4. **説明なしで使える UX**: 初見でもツールチップ・ステータスバーのガイド・妥当なデフォルト値だけで操作が完結することを非機能要件の柱とする。

ドキュメントの流れ:

```
スケッチ(点・線・円弧・面)
   ↓ フィーチャー(押し出し/回転/縫合/穴/面取り…)
部品(パート) ── 色・材質(外観)
   ↓ 配置・合致拘束
アセンブリ
   ↓ 三面図自動生成・寸法
図面(A3/A4) → PDF / JPEG
部品・アセンブリ → STEP / STL / 3MF / OBJ / glTF
```

## 4. 機能要件

要件 ID の凡例: `FR-カテゴリ番号-連番`。優先度は MoSCoW(Must / Should / Could)で表す。

### 4.1 3D ビューポートと視点操作(FR-1xx)

| ID | 要件 | 優先度 |
|---|---|---|
| FR-101 | マウスによる視点操作: 中ボタンドラッグでオービット、Shift+中ボタンでパン、ホイールでズーム(Blender 互換)。マウスのみ・タッチパッドでも代替操作を用意する | Must |
| FR-102 | 透視投影/平行投影の切り替え | Must |
| FR-103 | **ビューキューブ**: 画面右上に「前・後・右・左・上・下」を各面に表記した立方体を常時表示。ドラッグで視点回転、面・辺・頂点のクリックでその要素を正面とする視点へアニメーション遷移 | Must |
| FR-104 | グリッド・XYZ 軸の表示(表示/非表示切替、グリッド間隔は自動スケール) | Must |
| FR-105 | 表示スタイル: シェーディング/シェーディング+エッジ/ワイヤーフレームの切替 | Must |
| FR-106 | 選択: 頂点・辺・面・ボディ・スケッチ要素をクリック選択、ドラッグでボックス選択。選択候補のホバーハイライト、重なり要素の切替(クリック連打またはリスト) | Must |
| FR-107 | スナップ: 端点・中点・円中心・交点・グリッドへのスナップ。有効/無効の切替とスナップ種別のフィルタ | Must |
| FR-108 | 視点のホームポジション(等角視)へのワンキー復帰 | Should |
| FR-109 | 断面表示(任意平面でのクリッピング) | Could |
| FR-110 | **直交・極トラッキング**: 線を引くときに、向きを 0°/90°(直交)や 15° 刻みの角度へ吸着させられる。既存の点から伸ばした延長線・その点を通る垂線にも吸着し、吸着している間は案内線を表示する。入切と刻み角度は切り替えられる(スナップ FR-107 と併せて使う) | Should |
| FR-111 | **ビューの断面表示**: 形を切らずに、任意の平面で見た目だけをクリップして中を確かめられる(つまみで平面を動かせる)。切断面の指定は FR-432 と共有する | Should |
| FR-112 | **選択フィルタと選択セット**: 頂点・辺・面・ボディだけを選べる切替と、選んだ組に名前を付けて保存・呼び出しできる | Should |
| FR-113 | **名前付きビューと 4 分割表示**: いまの見え方に名前を付けて保存・復帰でき、三面図+立体の 4 分割表示ができる。図面(P8)の投影図の選び方にもつなぐ | Should |

※ **FR-108 の v1.14 の注**: **既定の視点(ホームポジション)は「前・上・右」の 3 面が見える等角**とする(利用者の指示 2026-09-06「初期状態は前と上と左右どちらかが見えた状態がいい」。左右は右を採る)。前は −Y・右は +X・上は +Z(ビューキューブ FR-103 の面の呼び名と同じ)なので、カメラは (+X, −Y, +Z) の側に置く。v1.13 までの既定は (+X, +Y, +Z) で、見えるのは上・右・**後ろ**だった。仰角(等角)と距離は変えていない。起動直後・新規文書・「視点を戻す」(Home キーとビューキューブの家)はすべてこの 1 つの向きを使い、FR-113 の名前付きビューの初期値もここから採る。FR-108 の行の文言・優先度は変えない。

### 4.2 数値・数式入力エンジン(FR-2xx)

| ID | 要件 | 優先度 |
|---|---|---|
| FR-201 | アプリ内の**すべての数値入力欄**で数式を受け付ける: 四則演算、括弧、累乗(`^`)、平方根・立方根など n 乗根(`sqrt()`, `cbrt()`, `root(x,n)`, `√` 記号入力)、分数(`3/4`)、円周率 `π`(`pi`)、定数 `e` | Must |
| FR-202 | 式は文字列のまま保存され、フィーチャー編集時に元の式が再表示・再編集できる(評価結果だけを保存しない) | Must |
| FR-203 | 式の評価は任意精度演算で行い、誤差を抑えた上で幾何カーネルへ渡す(カーネル自体は double 精度) | Must |
| FR-204 | 不正な式は入力欄上で即時にエラー表示し、理由(構文エラー、ゼロ除算等)を示す | Must |
| FR-205 | 角度入力は度(°)を既定とし、`rad()` 関数でラジアン指定も可能 | Must |
| FR-206 | ユーザー定義パラメータ(変数)表: 名前付き変数を定義し式から参照できる。変数変更で参照フィーチャーが再計算される | Should |
| FR-207 | **パラメータ表**: 名前を付けた数値(板厚・穴径など)を一覧のパネルで作り、名前・値(式)・説明を編集できる。どの数値欄からも名前で参照でき、表の値を 1 か所変えると参照しているところが全て追従する。使われていない名前と、参照が循環している名前は画面上で示す | Must |

| FR-209 | **設計表(構成)**: 名前を付けた数値(FR-207)の組を表で複数持ち、切り替えて保存できる。部品表(FR-728)にも出せる(Inventor の iPart / SolidWorks の構成に相当) | Should |

### 4.3 スケッチ(FR-3xx)

スケッチは 3D 空間への直接入力を基本とし、作業平面(XY/YZ/ZX・既存の平面フェイス・任意定義平面)を選択すると平面上への 2D 入力になる。

| ID | 要件 | 優先度 |
|---|---|---|
| FR-301 | **点のプロット(絶対座標)**: X, Y, Z を数式込みで指定して点を作成 | Must |
| FR-302 | **点のプロット(相対座標)**: 直前の点、または任意に選択した既存の点を基準に、シフト量(ΔX, ΔY, ΔZ)を指定して点を作成 | Must |
| FR-303 | 点のプロット(極座標): 基準点+方向(角度)+距離で点を作成 | Must |
| FR-304 | **線分**: 2 点間を結ぶ。または始点+方向・長さ・角度指定で作成 | Must |
| FR-305 | **円弧**: 中心点+半径+開始角度+終了角度で作成(作業平面上)。全周指定で円になる | Must |
| FR-306 | 3 点円弧(始点・終点・通過点)による作成 | Should |
| FR-307 | **連続描画**: 線・円弧の端点から続けて次の線・円弧を描ける(端点スナップ+チェーン入力モード) | Must |
| FR-308 | **点列生成**: 基準点+方向+間隔+個数を指定して、一直線上に等間隔の複数点を一括作成 | Must |
| FR-309 | **面の作成**: 同一平面上の閉ループ(線・円弧の連なり、または点列の順次接続)から面を作成。点のみを順に選んで面を張ることもできる(隣接点間に線が自動生成される) | Must |
| FR-310 | 面・立体の色指定: 作成された面・ソリッドは任意の色で塗りつぶし表示できる(既定色あり、面単位・ボディ単位で変更可) | Must |
| FR-311 | スケッチ要素の編集: 座標・長さ・角度・半径を後から変更でき、依存要素が追従する | Must |
| FR-312 | 非平面境界への面張り(フィリング) | Could |
| FR-313 | 幾何拘束(水平・垂直・接線・一致等の自動/手動拘束) ※本製品は座標・数値入力主体のため、拘束ソルバーは将来拡張とする | 将来 |

| FR-317 | **スプライン**: 指定した点を全て通る曲線(通過点)と、点で形を引っぱる曲線(制御点)の 2 通りで滑らかな曲線を描ける。点は後から追加・移動・削除でき、各点の座標は数式で指定できる | Must |

| FR-319 | 文字の輪郭化: 文字列・書体・文字高さを指定して、文字の輪郭をスケッチ要素として配置できる(刻印・銘板の下描き用) | Should |

## 6. システム構成・技術スタック

### 6.1 技術選定

| レイヤ | 採用技術 | 選定理由 |
|---|---|---|
| 言語 | TypeScript(strict) | Web/デスクトップ同一コード、型安全、情報量最多 |
| 幾何カーネル | OpenCASCADE (OCCT) の WASM ビルド(opencascade.js。必要に応じ Emscripten 自前ビルド) | 商用実績のある B-rep カーネル。ブーリアン・フィレット・STEP を自作せずに済む |
| 3D 描画 | Three.js(WebGL2) | カスタム CAD UI(ビューキューブ・スナップ表示等)の作り込みに最適 |
| UI フレームワーク | React + Zustand(状態管理) | コンポーネント資産・情報量 |
| 式エンジン | 自作パーサー + decimal.js(任意精度評価) | √・n乗根・分数・π・累乗の要件を満たす最小構成 |
| デスクトップ | Electron(Windows: NSIS インストーラ / Linux: AppImage) | Web 版とのレンダリング一致・配布容易性 |
| Web 配信 | Cloudflare Pages(静的配信、COOP/COEP ヘッダー設定) | 要件指定。サーバーレスで運用費ゼロ |
| 図面 → PDF | **自前で PDF 1.4 のパス命令を直接出力**し、**文字は opentype.js(MIT)で輪郭化して塗りで描く**(日本語の字体は Noto Sans JP(OFL 1.1)を同梱。P8 §0.a-0.10・0.11 の決定。v1.13 で `jsPDF + svg2pdf.js` から変更)。JPEG/PNG は Canvas ラスタライズ | 追加依存をフォント解析 1 件にとどめつつ、SVG/PDF/DXF/Canvas の 4 つの出口を同じ中間表現から作れる |
| カーネル実行 | Web Worker + Comlink | UI スレッド非ブロッキング(NFR-PF-4) |
| ビルド | Vite + pnpm workspaces(モノレポ) | 高速な開発サイクル |
| テスト | Vitest(ユニット)+ Playwright(E2E) | NFR-MA-2 |
| CI/CD | GitHub Actions | lint / test / build / リリース(electron-builder)/ Pages デプロイ |

バージョン方針: 依存はすべて lockfile で固定し、opencascade.js は特定バージョンにピン止めして更新は検証付きで行う。

### 6.2 パッケージ構成(モノレポ)

```
pointercad/
├── packages/
│   ├── expression/      # 式パーサー・任意精度評価(依存なしの純粋ロジック)
│   ├── kernel/          # OCCT WASM ラッパー(形状生成・ブーリアン・面取り・テッセレーション・STEP/STL 変換)
│   ├── model/           # ドキュメントモデル: フィーチャー履歴・部品・アセンブリ・再計算エンジン・Undo
│   ├── drawing/         # 図面生成: 投影(HLR)・寸法・JIS スタイル・SVG 生成
│   ├── io/              # .pcad 形式、STEP/STL/3MF/OBJ/glTF 入出力、PDF/JPEG 出力
│   ├── ui/              # React コンポーネント群: ビューポート・ビューキューブ・ツリー・入力欄・ヘルプ
│   └── help-content/    # ヘルプ文書(Markdown)
├── apps/
│   ├── desktop/         # Electron シェル
│   └── web/             # Web 版エントリ(Cloudflare Pages)
└── docs/                # 本書・設計文書
```

依存方向は `apps → ui → model → kernel/expression` の一方向とし、逆流を禁止する。

### 6.3 データフロー

```
ユーザー操作(UI)
  → コマンド発行(Undo 履歴に記録)
  → ドキュメントモデル更新(フィーチャー追加/編集)
  → 再計算エンジン(変更以降のフィーチャーのみ。結果キャッシュ)
  → kernel(Web Worker 内の OCCT)で B-rep 生成
  → テッセレーション → Three.js シーン更新
```

## 10. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| opencascade.js のメンテ停滞・バージョン遅れ | カーネル更新不能 | Emscripten による OCCT 自前 WASM ビルド手順を早期(P0)に確立し、逃げ道を確保 |
| フィレット・ブーリアンの失敗(B-rep カーネルの宿命) | 操作不能・データ破損 | 失敗を前提とした UI(FR-504, NFR-RE-1)。適用前プレビューと検証 |
| WASM メモリ上限(〜4GB) | 大規模モデルで停止 | 想定規模の明示(§5.2)、警告表示、結果キャッシュの LRU 破棄 |
