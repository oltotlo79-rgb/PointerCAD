# 8. 設計の規律

要件の正本は `docs/requirements.md`。ここではコードを書くときに常に守る原則だけを抜き出す。

- **幾何計算はdouble + 明示的な許容誤差を原則とする。** 厳密値(√・分数・π・累乗)を扱うのは `packages/expression` の中だけとし、式は文字列のまま保存、評価は任意精度、カーネル(OCCT)へはdoubleへ丸めて渡す(FR-202/203)。厳密演算を幾何計算・描画へ全面適用しない。全面的な厳密演算は前例(ORIGAMI2)で肥大化を招いたため。
- **止めずに警告する。** フィーチャーの再計算失敗(フィレット不成立等)でクラッシュせず、操作をブロックするゲートも作らない。エラー箇所をツリー上で明示し、修正または取り消しを促す(FR-504、NFR-RE-1)。
- **フロントの状態はZustandストア1本に一元化する。** コンポーネントの `useState` はホバー等、表示専用の一時状態だけに使う。状態の分散は保守を困難にするため。
- **パッケージの依存方向は `apps → ui → model → kernel / expression / drawing` と `ui → fem → model` の一方向とする。** FEMはmodelを使う計算層とし、modelからFEM、FEMからui / apps / io / help-contentへの依存は型だけでも禁止する。FEMの契約にUIや保存層の型を持ち込まない。 `drawing` は kernel / model / ui / io に依存しない葉とし、UIから幾何カーネルへ直接依存しない。逆流や横流しを見つけたら設計の欠陥として直す(NFR-MA-1)。
- **純数値スプライン共有の限定入口。** modelの`kernelBridge/splineMath.ts`だけが`@pointercad/kernel/math/spline-interpolation`を参照できる。このsubpathは型を含めimportを持たず、OCCT・WASM・Worker・modelに依存しない。他のmodel経路からkernelの実行処理を借りる許可にはしない。
- **純数値ベクトル共有の限定入口。** modelの`kernelBridge/vectorMath.ts`だけが`@pointercad/kernel/math/vector-arithmetic`を参照し、`sketch/vec3.ts`から同じ純関数を使う。このsubpathは型を含めimportを持たず、四元数の有限判定と点の加算だけを行う。kernelのindex・OCCT・WASM・Workerは読み込まない。依存の逆流とUIからkernelへの直接参照は禁止のまま、入口と依存0件を通常試験で検査する。
- **純数値の大きさの比べの共有の限定入口。** modelの`kernelBridge/magnitudeMath.ts`だけが`@pointercad/kernel/math/magnitude`を参照し、kernelの中は`occt/tolerances.ts`が同じ関数を出し直す。このsubpathは型を含めimportを持たず、大きさと許容差の比べの純関数だけを持つ。kernelのindex・OCCT・WASM・Workerは読み込まない。入口と依存0件は通常試験（`packages/test-utils` の `splineArithmeticBoundary.test.ts`）で検査する（2026-11-22、21 回目の送信で追加）。
- **幾何カーネルはWeb Worker内で実行する。** UIスレッドで幾何演算をしない。計算中も進捗表示とキャンセルが効くこと(NFR-PF-4)。
- **導出できるものは保存しない。** `.pcad` に保存するのはフィーチャー履歴・式・拘束・図面定義だけとし、B-repやメッシュは再計算で導出する(§8)。保存状態の不整合を避けるため。
- **説明を読まなくても直感的に触れるUIにする。** NFR-UX-1〜7を全ツールで守る。固定区画(ツールバー / ツリー / ビューポート+ビューキューブ / プロパティ / ステータスバー)を増やさない(§7.1)。要素の平置きは前例で画面を複雑にしたため。
- **機能追加はヘルプとテストの同時追加を必須とする**(FR-901、NFR-MA-4)。ヘルプに無い機能はリリースに含めない。
- **Web版とデスクトップ版に機能差を作らない**(§1.5)。プラットフォーム固有コードは `apps/` 配下だけに置く。
- **UI文字列はすべてリソースファイル(ja.json)に分離する**(NFR-MA-5)。コンポーネントへ直書きしない。
- **検査の集合は正本から導く。** 登録表と定義は安定した識別子で照合する。順序・件数が仕様に含まれる場合はその条件を保持する。寸法・質量・形と個別行の期待値は、独立した原票、手計算、既知の実例で照合する。
- **設計の契約は通常の入口で守る。** 型・lintで施行できる契約はその正本に置き、待機・取消・失敗・データ境界は実際の読者の挙動を検査する。保証の置換では同じ入力で元の保証が残ることを確かめる。生成名簿は所定の生成入口を使う。関数・引数・入れ子の上限は根のESLint設定と既存基準表を参照する。
- **許容差はパッケージの正本を使う。** 依存0件の計算入口では比較の定義を正本と照合し、単位・演算順・等号・NaNの扱いを保持する。
- **利用者に示す失敗は理由コードと差し込み値で渡す。** UI が表示リソースの鍵を解決し、コードと鍵の対応を型で照合する。開発者向けの原因は診断の記録に残す。リソース鍵の重複は既存の検査で止める。
- **焦点・文言・欄選びの共有入口を使う。** 対象のモーダルは共有処理で焦点を戻し、ブラウザーの既定のキー操作を保持する。新規・変更する画面操作の検査では表示文をリソースから得る。欄は対応する共通補助で探し、同名の欄は範囲を限定する。ボタンは役割と名前で探す。
- **振る舞いを変える前に既存の読者を照合する。** 入力条件、出力、保持する境界を明記し、実装、呼出し、既存の試験と表の実パスと基点の指紋を結ぶ。個別作成・合成・検査の開始前に最終実装と読者の実バイトを再照合する。確定できない依存は読む対象を明示して提出を止める。
