## 5. 道具と手順（v1.0.2 の引き継ぎ書 §5 と同じ所は省く）

### 5.1 配達（コミット→検査→送信）
- 部分だけ送る時: `python -B -X utf8 scratchpad/claude/tools/snapshot_only.py <含めるパス...> [--allow-revert <パス>...]`（他の全ての変更を除外してスナップショット。今日統括が作った）。全部送る時は `deliver.py snapshot`。
- 続き: `deliver.py sync --delivery <ID> --dry-run` → `sync` → c3 で `git write-tree` → 承認ファイル `scratchpad/c3/.git/pointercad-commit-batch-approval.json`（新しく Write で書く。base=HEAD・tree=write-tree の値・recordedAt=今の時刻）→ コミットの文（日本語・接頭辞なし・BOM なし。`python -B -X utf8 scripts/lib/commit_message.py <file>` で確かめる）→ `deliver.py gate --delivery <ID> --message <file> --push-ref refs/heads/feature/quality-20261004 --scope local --e2e-lock stage` → 合格後 `sync-root --dry-run` → `sync-root`。
- gate.log の `[NG]` のうち、品質ゲートの自己試験がわざと出す物（約16行）は失敗ではない。`state.json` の status/exitCode で判断する。
- **注意（依存の置き換え）**: 作業ツリーの node_modules は旧のまま。c3 での gate が lock との食い違いで止まる場合は、c3 で `pnpm install --frozen-lockfile` が要る（統括は pnpm を直接実行しないので、担当に流させるか check.ps1 の手順に従う）。

### 5.2 検査（diag.py）の環境
- 必ず同じ呼出しの先頭で:
  - `export PATH="$(pwd)/scratchpad/claude/agents/cx-v103-e2e-input-sol/private-toolchain/bin:$PATH"`
  - `export PCAD_DIAG_NORMAL_PRIORITY=1 PCAD_DIAG_UNIT_MAX_WORKERS=2 PCAD_DIAG_HEAVY_SLOTS=4`
- ui の全件は Windows のコマンド長の制限で一度に流せない。3〜4分割する（担当の final.md に分け方の例）。
- 画面検査は3環境: `--project=functional --project=firefox --project=electron`。Firefox は `e2e/playwright.config.ts` の testMatch の許可名簿に spec 名を足さないと流れない。
- **Codex の担当（`PCAD_WORKER_KIND=codex`）は `diag.py e2e` を拒否される**。画面検査は統括（Codex の根）が流すか、別の手段を決める。
- Codex の担当の環境は GitHub の API に繋がらないことがある。gh の確認は統括が行う。

### 5.3 Codex で統括する時の注意
- Claude Code のフック（`.claude/hooks/`）は Codex では自動で働かない。フックが止めていた誤りを自分で避ける: 統括の pnpm 直接実行、Bash のヒアドキュメントや python -c の中の逆斜線、未来の時刻、担当の wait の重ね（for の中も）、承認の無い main への送信。
- rules/00 の「Codexの明示読取・委譲・報告ガード」（codex_work_status.py・v103_publish_report.py 等）は Codex 用の明示 CLI。ただし利用者は「Codex の進捗がいまいち」と Claude へ替えた経緯がある。**原票・SHA・ACK の儀式に時間を使い過ぎない**こと。根拠のファイルと検査の結果だけは必ず残す。

### 5.4 既知の道具の問題（直していない）
- **diag.py の画面検査の排他が先着順でない**（20秒ごとの取り合い）。後から出した RUN が先に取り、75分以上待つ担当が出た。FIFO の待ち行列にする直しが要る。
- 担当が多く並行で重い時、性能の記録が目標を超える（§4.3 の3）。
- `release_publish.ps1` は PowerShell 5.1 で文字化けを直した版（10-03）。
