# 8. 設計の規律

要件の正本は `docs/requirements.md`。ここではコードを書くときに常に守る原則だけを抜き出す。

- **幾何計算はdouble + 明示的な許容誤差を原則とする。** 厳密値(√・分数・π・累乗)を扱うのは `packages/expression` の中だけとし、式は文字列のまま保存、評価は任意精度、カーネル(OCCT)へはdoubleへ丸めて渡す(FR-202/203)。厳密演算を幾何計算・描画へ全面適用しない。全面的な厳密演算は前例(ORIGAMI2)で肥大化を招いたため。
- **止めずに警告する。** フィーチャーの再計算失敗(フィレット不成立等)でクラッシュせず、操作をブロックするゲートも作らない。エラー箇所をツリー上で明示し、修正または取り消しを促す(FR-504、NFR-RE-1)。
- **フロントの状態はZustandストア1本に一元化する。** コンポーネントの `useState` はホバー等、表示専用の一時状態だけに使う。状態の分散は保守を困難にするため。
- **パッケージの依存方向は `apps → ui → model → kernel / expression / drawing` の一方向とする。** `drawing` は kernel / model / ui / io に依存しない葉とし、UIから幾何カーネルへ直接依存しない。逆流や横流しを見つけたら設計の欠陥として直す(NFR-MA-1)。
- **幾何カーネルはWeb Worker内で実行する。** UIスレッドで幾何演算をしない。計算中も進捗表示とキャンセルが効くこと(NFR-PF-4)。
- **導出できるものは保存しない。** `.pcad` に保存するのはフィーチャー履歴・式・拘束・図面定義だけとし、B-repやメッシュは再計算で導出する(§8)。保存状態の不整合を避けるため。
- **説明を読まなくても直感的に触れるUIにする。** NFR-UX-1〜7を全ツールで守る。固定区画(ツールバー / ツリー / ビューポート+ビューキューブ / プロパティ / ステータスバー)を増やさない(§7.1)。要素の平置きは前例で画面を複雑にしたため。
- **機能追加はヘルプとテストの同時追加を必須とする**(FR-901、NFR-MA-4)。ヘルプに無い機能はリリースに含めない。
- **Web版とデスクトップ版に機能差を作らない**(§1.5)。プラットフォーム固有コードは `apps/` 配下だけに置く。
- **UI文字列はすべてリソースファイル(ja.json)に分離する**(NFR-MA-5)。コンポーネントへ直書きしない。
