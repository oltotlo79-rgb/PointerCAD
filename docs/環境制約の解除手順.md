# VSCodeのターミナルで、CodexからGitHubへ作業結果を保存するための手順

更新日：2026年10月6日

利用者から「VSCodeのターミナルを使っている」と確認できたため、その環境に合わせて修正しました。以前の、入力欄の近くに「権限」「Permissions」「Default permissions」を探す案内は、アプリ画面向けでした。

**まず、今Codexと会話している入力欄に `/permissions` と入力し、Enterを押してください。** 以下で入力する場所と、その後の操作を説明します。[OpenAI公式のCodex操作一覧](https://learn.chatgpt.com/docs/developer-commands?surface=cli)

## 1．入力する場所を確認する

1. VSCodeを開き、画面下の「ターミナル」を表示してください。
2. ターミナルが複数ある場合は、今回のPointerCADについてCodexと会話しているものを選んでください。
3. 普段、私への指示を入力している欄をクリックしてください。
4. 入力中の文章があれば、先にコピーして手元に残してください。
5. 次の1行だけを入力し、Enterを押してください。先頭の `/` も必要です。

```text
/permissions
```

これはCodex内の操作です。`PS C:\...>` が表示された、通常のPowerShellの命令入力欄へ入力するものではありません。VSCodeの「設定」やWindows全体の設定を開く必要もありません。

Codexが処理中で操作を受け付けない場合は、入力できるまで待ってください。この設定を開くために、実行中の試験を強制終了する必要はありません。

公式の説明では、ターミナル版Codexの `/permissions` から、この会話で使う許可設定を選べます。[OpenAI公式の説明](https://learn.chatgpt.com/docs/sandboxing)

## 2．表示された選択肢から許可方法を選ぶ

メニューが開いたら、**「Ask for approval」または「承認を求める」** があるか確認してください。

該当する項目があれば、画面の操作案内に従って選んでください。上下の矢印キーで項目を動かす形式なら、目的の項目に合わせてEnterで確定します。

この設定は、通常はPointerCADのフォルダー内で作業し、追加の許可が必要な操作では利用者へ確認するものです。GitHubへの接続などが必要なときに、確認を出せる状態にします。[OpenAI公式の許可方法の説明](https://learn.chatgpt.com/docs/sandboxing)

名前が異なる場合は、表示されている名前と説明をそのままこの会話へ送ってください。画面をこちらで確認できていないため、「Auto」などの名前だけで同じ設定と決めつけません。

設定を選んだだけで、変更履歴の保存とGitHubへの送信が成功したとは扱いません。実際に反映された許可と操作結果を、こちらで確認します。

## 3．選択後、Codexへ確認を依頼する

普段の会話入力欄に戻り、次を送ってください。コピーして使えます。

```text
/permissionsで「Ask for approval」を選びました。
今の会話に反映されているか確認してください。
PointerCADの変更履歴を保存し、GitHubへ送れるかを確認して進めてください。
制限が残る場合は、実際の失敗内容と次に必要な操作を報告してください。
```

別の名前を選んだ場合は、「Ask for approval」の部分を実際の名前に置き換えてください。

こちらでは、次の順に確認します。

1. 今の会話が追加の許可を求められる設定になったか。
2. PointerCADの変更履歴を保存できるか。
3. GitHubへ接続できるか。
4. 検査済みの作業結果を送信できるか。

利用者から「プッシュしていい」という指示は、すでに受領しています。同じ許可をもう一度尋ねるための手順ではありません。

## 4．操作の許可を求める表示が出た場合

Codexのターミナル内に、実行したい操作と許可の選択肢が表示される場合があります。

表示された内容が、PointerCADの変更履歴の保存、またはGitHubへの接続・送信であることを確認し、目的に合う操作を許可してください。選択方法は、その画面の案内に従ってください。

確認が出ないまま失敗した場合は、次を送ってください。

```text
設定は選びましたが、操作の許可を求める表示は出ていません。
現在の許可設定と、失敗した操作を確認してください。
```

確認表示が出ないことだけでは、制限が解除されたか判断できません。こちらで実際の状態を調べます。

## `/permissions` が使えない・選択できない場合

エラーになった場合は、その文章をそのままこの会話へ送ってください。メニューが開いても目的の項目がない、項目を選べない、選んでも戻る場合は、見えている選択肢と説明を送ってください。

```text
VSCodeのターミナルで /permissions を入力しました。
表示された内容は次のとおりです。
（ここに表示された文章、選択肢、エラーを貼り付ける）
```

それ以上の設定変更や、Codexの再起動を先に行う必要はありません。表示内容から、使用中のCodexの違い、起動時の設定、管理者側の制限などを切り分けます。現時点では、どれが原因か未確認です。

組織の設定によって、選択できる許可方法が制限される場合があります。その場合も、実際の表示を確認してから必要な対応を案内します。[OpenAI公式の許可方法の説明](https://learn.chatgpt.com/docs/sandboxing)

## 設定を選んでもGitHubへ接続できない場合

1. 普段使っているEdgeやChromeを開いてください。
2. アドレス欄に `https://github.com` と入力してください。
3. ページが表示されるか確認してください。
4. この会話へ「通常のブラウザではGitHubが開ける」または「通常のブラウザでもGitHubが開けない」と送ってください。

ブラウザで開けることは、Codexから送信できることの証明にはなりません。Codex側の接続制限が残っているかを、別に確認します。

## 再起動が必要と分かった場合

まず、次をこの会話に送ってください。

```text
設定を反映するため、Codexを再起動したいです。
今の作業を安全な区切りまで進め、変更ファイルの控えと次の作業を保存・記録してください。
再起動してよい状態になったら報告してください。
```

こちらで実行中の検証を適切に終え、作業結果と引継ぎを保存します。準備完了の報告を受けてから、Codexを終了し、PointerCADの同じフォルダーで同じ会話を再開してください。

```text
Codexを再起動しました。
保存した記録から作業を再開し、変更履歴の保存とGitHubへの送信を確認してください。
```

この手順書の修正だけで、作業中断の指示を受けたとは扱いません。別プロジェクトORI3の試験も継続します。

## 追加確認：GPUの使用量を記録するためのWindowsの許可

2026年10月7日00:11、GPUが使うメモリーの量を記録する準備を実際に試しました。Windowsから「アクセスが拒否されました。管理者として実行してください」と返りました。記録を始める前に停止しており、ORI3の試験や他の記録を停止していません。失敗した原記録は `scratchpad/claude/inspections/v103-gpu-etw-capability-20261007001144b731d3856e/receipt.json` です。

Codexのフルアクセス設定は反映されています。ここで必要なのは、Windowsの記録機能を使うための追加の許可です。Microsoftも、管理者の許可を持つ利用者が記録機能を操作する場合は、操作する画面を「管理者として実行」で開く方法を説明しています。[Microsoft公式の説明](https://learn.microsoft.com/en-us/windows/win32/api/evntcons/nf-evntcons-eventaccesscontrol)

現在のVSCodeとORI3の画面は開いたままで、次の方法で別の画面を開けるか確認できます。

1. Windowsの「スタート」ボタンを右クリックします。
2. 「ターミナル（管理者）」があれば選びます。見つからない場合はスタートの検索欄へ「PowerShell」と入力し、表示されたPowerShellを右クリックして「管理者として実行」を選びます。
3. Windowsの確認画面が表示されたら、アプリ名がWindows TerminalまたはPowerShellであることを確認します。自分のアカウントで許可できる場合は開きます。
4. パスワードを求められ、自分では許可できない場合は、その場で閉じて構いません。パスワードをこの会話へ送る必要はありません。
5. この会話へ「管理者として別のターミナルを開ける」または「管理者としては開けない」と知らせてください。

管理者としてPowerShellを開けたことを確認した後は、その画面に次の1行を貼り付け、Enterを押します。開いた場所が `C:\Windows\system32` のままでも実行できます。

```powershell
& "C:\Users\oltot\AppData\Local\Programs\Python\Python312\python.exe" -B -X utf8 "C:\Users\oltot\Documents\git-projects\PointerCAD\scratchpad\claude\instructions\v103-codex61-root-gpu-etw-capability.py"
```

この確認は、PointerCAD用に新しく作った名前の記録だけを開始し、その記録だけを終了します。結果と原記録はプロジェクト内の `scratchpad/claude/inspections/v103-gpu-etw-capability-...` に保存されます。管理者の画面かどうかも実際に記録します。ORI3や他の記録を停止する操作は含みません。

## 管理者PowerShellで「指定されたファイルが見つかりません」と出た場合

2026年10月7日06:42の表示は、確認処理が使う検索プログラム「rg」を管理者の画面から見つけられなかったことが原因です。PythonやPointerCADのファイルが消えたという意味ではありません。この試行ではGPUの記録を開始していません。失敗した記録はそのまま保存しています。

検索プログラムの場所を明示する修正版を用意しました。すでに開いている「管理者」のPowerShellに、次の1行だけを貼り付けてEnterを押してください。画面に出ている `PS C:\Windows\system32>` の部分は貼り付けません。現在の場所は変更しなくて構いません。

```powershell
& "C:\Users\oltot\AppData\Local\Programs\Python\Python312\python.exe" -B -X utf8 "C:\Users\oltot\Documents\git-projects\PointerCAD\scratchpad\claude\instructions\v103-codex61-root-gpu-owned-smoke-path-fixed.py"
```

修正版は、必要なプログラムと元の確認処理が用意した内容のままか確かめてから、元の事前確認を通して実行します。Windows全体の設定変更やプログラムの再インストールは必要ありません。結果はプロジェクト内へ保存されます。この短い確認の成功だけで、実アプリのGPUメモリー使用量や性能が合格したとは扱いません。

表示が止まってPowerShellの入力欄へ戻ったら、表示された結果をこの会話へ送ってください。`Preflight refused` が出た場合も、同じ命令を何度も実行せず、その結果を送ってください。報告・監視の有効期限はこちらで整えます。以前の `gpu-etw-capability.py` や修正版の付いていない `gpu-owned-smoke.py` の実行は、今回の再確認には使いません。
