# 命名の辞書

この辞書は、対象の意味に合う語を選ぶための指針である。公開API、保存キー、
通信キー、外部ライブラリの正式名、数学の記号は互換性と意味を保つ。既存の
契約を変える場合は利用側も含めて別途確認する。語が異なっても同じ意味とは
限らないため、機械的に一括置換しない。

## 概念別の使い分け

| 概念 | 語の使い分け |
|---|---|
| 立体（形状の結果） | `body` はフィーチャーの結果、`shape` はカーネル内のOCCT形状、`solid` はソリッドや画面の立体機能に使う。B-repは表現形式を示す。 |
| 組立ての配置 | `component` は文書の要素、`occurrence` は入れ子を展開した実体、`placement` は位置と向きの値。`instance` は対象を確認して使い分ける。 |
| 識別子 | `id` は保存する識別子、`key` はキャッシュやMapなどの導出鍵、`ref` は別の文書・ファイル等への参照。`handle` は所有や寿命を持つ取っ手に使う。 |
| フィーチャー | 文書のフィーチャーは `feature`、処理や演算は `operation`。局所的な省略 `op` は避ける。 |
| スケッチの要素 | `element` は図面・梁の要素、`entity` はDXFの実体、`item` は一覧の項目、`primitive` は基本形状。`geometry` は幾何そのものを示す。 |
| 文書 | 部品やアセンブリの文書は `document`。局所的な省略 `doc` は避け、モデルやプロジェクトを意味する場合は区別する。 |
| 部品 | `part` は部品、`member` は梁の部材、`component` は組立ての要素。 |
| 合致・関節 | `mate` は合致拘束、`joint` は関節・機構、`constraint` はスケッチ等の拘束、`connection` は締結等の接続。 |
| 辺 | `edge` はB-repの辺、`curve` は幾何の曲線、`segment` は線分や曲線の区間。 |
| 面 | `face` はB-repの面、`surface` は曲面の幾何や曲面フィーチャー。 |
| 点 | `point` は座標・スケッチの点、`vertex` はB-repの頂点、`corner` は角やその処理。 |
| パラメータ | パラメータは `parameter`、式の変数は `variable`。局所的な省略 `param` は避ける。 |
| 式 | 式は `expression`、方程式は `equation`。局所的な省略 `expr` は避け、`formula` は対象の意味を確認する。 |
| 寸法 | `dimension` は寸法、`measurement` は測定結果、`measure` は測定する操作。 |
| 許容誤差 | 数値の許容差は `tolerance`。幾何公差は `gdt` 等の文脈を付けて区別する。ライブラリや数学の正式名は意味を保つ。 |
| 再計算 | 履歴の再計算は `recompute`、参照の解決は `resolve`、式の評価は `evaluate`。 |
| 保存（書き出し） | `save` は利用者の保存、`serialize` は文書から保存表現への変換、`export` は他形式への書き出し、`write` はバイト列等の書込み。 |
| 読込み | `read` はデータの読取り、`decode` は符号化データから値への変換、`parse` は文字列等の構文解析、`load` は実行部・資源の読込み。 |
| 失敗の情報 | `Error` はthrowする型、`Failure` は結果型の失敗側、`Issue` は入力検証の指摘。診断や警告は実際の役割を確認する。 |
| 利用者向けの文言 | `message` は文、`label` は欄の名前、`title` は見出し、`text` は任意の文字列。 |
| 設定 | `settings` は利用者の設定、`options` は呼出しの選択肢・引数。外部APIの設定名はその契約を保つ。 |
| 世代・版 | `version` は保存形式の版、`revision` は文書内容の版、`generation` は再計算や所有の世代。Unix時刻は時刻と分かる名にし、正当な既存 `EpochMs` 観測名も保つ。 |
| 表示用の三角形 | `mesh` はデータ、`tessellate` は処理、`triangle` は三角形。 |
| 削除 | `remove` は要素を除く、`clear` は全体を空にする、`delete` はOCCTの削除やファイル削除等に使う。 |
| 作成 | `create` は文書要素や値の作成、`make` は主にカーネルのOCCT作成、`build` は導出構造の構築。 |
| 検証 | `validate` は指摘を返す検証、`assert` は不成立時にthrow、`is…` は真偽を返す。 |
| 作業平面 | 作業平面は `workPlane`、幾何の平面は `plane`。`datum` は基準を意味する場合に区別する。 |
| 角度の単位 | 角度の単位を名前に付ける場合は `Degrees` または `Radians` を使う。 |
| 色 | 色は `color` を使う。 |
| 件数 | 個数は `Count` を使う。`size` はバイト数や寸法など、個数と異なる意味を保つ。 |

## 局所名と検査

関数内と非公開のモジュール内では用途が分かる名前を選び、`op`、`param`、
`expr`、`doc` の完全一致名を避ける。`epoch` が世代なら `generation`、
時刻なら時刻と分かる名前にする。既存の正当なUnix時刻の `EpochMs` は保持できる。

局所名検査は上記の完全一致名と、camelCase等の語に分けた複合名を確認する。
元監査の件数は参照回数ではなく宣言名の語の件数であり、完全一致名の件数とは
異なる。公開される `PatternDrawCommand.op` と `booleanOp` は既存契約として保つ。
