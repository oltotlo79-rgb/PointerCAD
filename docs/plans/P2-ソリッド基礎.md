# P2「ソリッド基礎」実装計画書

> **作業担当(サブエージェント)向け:** 本計画は `superpowers:subagent-driven-development`(推奨)または `superpowers:executing-plans` でタスク単位に実行する。各手順は `- [ ]` のチェックボックスで進捗を追う。
> **gitへの書き込みは統括だけが行う。** 作業担当は commit / push / checkout / merge / stash / reset を一切行わない(`rules/01-役割と委譲.md` §1)。

**目的:** 要件 `docs/requirements.md` §9 の P2 完了条件「簡単な部品を作って保存・再編集できる」を満たす。範囲は押し出し・回転・縫合・ブーリアン・フィーチャーツリー・Undo/Redo・`.pcad` 保存/読込・自動保存(FR-401〜404、FR-501〜505、FR-801、FR-805、FR-806)。

**構成方針:** P1 の `SketchDocument` を包み込む `PartDocument`(スケッチ群+ソリッドフィーチャー履歴)を `packages/model` に置き、全パラメータを**式文字列+評価値のペア**(`ExpressionValue`)で持つ(要件§8、FR-202)。参照はすべて id で持ち、座標や形を複製しない(FR-311、FR-502)。再計算は履歴順に 1 段ずつ行い、**未変更の段はカーネル側の形状キャッシュで作り直さない**(NFR-PF-3)。OCCT の形は Worker の中だけに置き、UI へは三角形と稜線だけを渡す(NFR-MA-1、NFR-PF-4)。Undo/Redo は文書の不変スナップショットで実現する(FR-505)。`.pcad` は ZIP コンテナ(`document.json` + `thumbnail.png`)で、スキーマ版を内包する(要件§8)。

**技術構成:** TypeScript(strict) / opencascade.js(OCCT WASM、Worker + Comlink)/ fflate(ZIP)/ decimal.js(式)/ Three.js / React + Zustand / IndexedDB(自動保存)/ Electron の `dialog` + IPC(デスクトップの保存)/ Vitest / Playwright

## 2. 技術方式

### 2.1 部品文書のデータモデル(要件§8、FR-202、FR-501)

`packages/model/src/part/types.ts`(新規)。P1 の `SketchDocument` はそのまま部品の中へ入る。

```ts
import type { ExpressionValue } from '@pointercad/expression';
import type { SketchDocument } from '../sketch/types.js';
import type { Vec3 } from '../sketch/vec3.js';

/** スケッチの面フィーチャー1枚への参照。座標は複製せず id だけを持つ(FR-311)。 */
export interface SketchFaceRef {
  readonly sketchId: string;
  readonly faceFeatureId: string;
}

/** スケッチの線分フィーチャー1本への参照(回転軸に使う)。 */
export interface SketchLineRef {
  readonly sketchId: string;
  readonly lineFeatureId: string;
}

export type SolidFeatureKind = 'extrude' | 'revolve' | 'sew' | 'boolean';

interface SolidFeatureBase {
  readonly id: string;
  /** フィーチャーツリーの表示名(FR-501)。 */
  readonly name: string;
  /** 抑制(FR-503)。true なら再計算で飛ばし、ボディを作らない。 */
  readonly suppressed: boolean;
}

/** 押し出し(FR-401)。テーパーは P3(§0.a-0.8)。 */
export interface ExtrudeFeature extends SolidFeatureBase {
  readonly kind: 'extrude';
  readonly profile: SketchFaceRef;
  /** 押し出す長さ(mm)。正の数。向きは reversed で決める。 */
  readonly distance: ExpressionValue;
  /** 面の法線と逆向きへ出すか。 */
  readonly reversed: boolean;
  /** 両側へ出すか。true なら距離の半分ずつ両方向。 */
  readonly symmetric: boolean;
}

/** 回転軸の指定(FR-402、§0.a-0.9)。 */
export type RevolveAxis =
  | { readonly kind: 'worldAxis'; readonly axis: 'x' | 'y' | 'z' }
  | { readonly kind: 'sketchLine'; readonly line: SketchLineRef };

export interface RevolveFeature extends SolidFeatureBase {
  readonly kind: 'revolve';
  readonly profile: SketchFaceRef;
  readonly axis: RevolveAxis;
  /** 回転角(度)。0 より大きく 360 以下。 */
  readonly angle: ExpressionValue;
  readonly reversed: boolean;
}

/** 縫合(FR-403)。閉じた殻を作れる面を並べる(§0.a-0.7)。 */
export interface SewFeature extends SolidFeatureBase {
  readonly kind: 'sew';
  readonly faces: readonly SketchFaceRef[];
  /** つなぎ目とみなす許容量(mm)。既定 0.01。 */
  readonly tolerance: ExpressionValue;
}

export type BooleanOperation = 'union' | 'subtract' | 'intersect';

/** ブーリアン(FR-404)。対象と相手のボディを消費して1つのボディを作る(§0.a-0.5)。 */
export interface BooleanFeature extends SolidFeatureBase {
  readonly kind: 'boolean';
  readonly operation: BooleanOperation;
  /** 残る側のボディを作ったフィーチャーの id。 */
  readonly targetFeatureId: string;
  /** 相手のボディを作ったフィーチャーの id。 */
  readonly toolFeatureId: string;
}

export type SolidFeature = ExtrudeFeature | RevolveFeature | SewFeature | BooleanFeature;

/** 部品(パート)ドキュメント。これが Undo のスナップショットの単位で、.pcad に保存される唯一のもの。 */
export interface PartDocument {
  readonly id: string;
  readonly name: string;
  /** スケッチ群。P2 の UI は1本だけ作るが、形は最初から複数を許す。 */
  readonly sketches: readonly SketchDocument[];
  /** ソリッドフィーチャーの履歴。順序が意味を持つ(要件§2「履歴パラメトリック」)。 */
  readonly features: readonly SolidFeature[];
}
```

**保存しないもの:** 解決済みの座標、B-rep、メッシュ、キャッシュの鍵、選択・ホバー・視点(`rules/04-設計の規律.md`「導出できるものは保存しない」)。

### 2.2 ボディの同一性と参照(§0.a-0.5)

- フィーチャー1つが作るボディは最大1つで、**ボディの id = フィーチャーの id**。
- ブーリアンは `targetFeatureId` と `toolFeatureId` のボディを**消費**する。消費されたボディは表示されない。
- 「いま画面にあるボディ」= 履歴を先頭から見て、**まだ消費されておらず、抑制されておらず、作成に成功したフィーチャー**のボディ。
- 消費の判定は `resolvePart` が1回の走査で決める。同じボディを2回消費しようとしたら、後の方を `missingBody` の失敗にする(止めずに理由を出す、FR-504)。

### 2.3 名前と id の採番(§0.a-0.19、P1 の残件)

`packages/model/src/sketch/createSketchDocument.ts` の `nextFeatureName` / `nextFeatureId` を、**既存の名前・id から連番を読み取って最大値+1** にする。ソリッド側も同じ関数を使う。

```ts
/** 「点1」「押し出し3」のような名前から末尾の数字を読む。読めなければ 0。 */
export function nameSerial(name: string, label: string): number;

/** 同じ接頭辞の既存 id の最大連番 + 1 の id を作る。 */

```

ソリッドの既定名: 押し出し=`押し出し`、回転=`回転`、縫合=`縫合`、和=`和`、差=`差`、積=`積`(ブーリアンは演算ごとに別の連番)。

### 2.4 カーネルへの API(NFR-MA-1、NFR-PF-4)

### 2.5 再計算とキャッシュ(NFR-PF-3、要件§6.3)

```
文書が変わる
  → model: resolveSketch(各スケッチ)          … P1 のまま
  → kernel: tessellateSketch(面があるときだけ) … P1 のまま
  → model: resolvePart(履歴を1段ずつ解決し、鍵を計算)
  → kernel: recomputeSolids(段の一覧を1回で渡す)
      各段について
        鍵がキャッシュにある → 形とメッシュをそのまま使う(cacheHits + 1)
        無い                 → OCCT で作り、三角形にして、鍵で覚える
      失敗した段は理由を残して次の段へ進む(FR-504)
  → model: 結果を model の型へ詰め替えて返す
  → ui: 三角形と稜線を three.js のシーンへ入れる
```

**鍵の作り方(§0.a-0.20).** `packages/model/src/part/cacheKey.ts`:

```ts
/** FNV-1a を 32 ビット2本(オフセットが違う)で回し、16 桁の16進にする。 */
export function hash64(text: string): string;
/** 1段ぶんの鍵。上流の鍵を混ぜるので、上流が変われば下流も必ず変わる。 */
export function solidStepKey(plan: SolidStepPlan, inputKeys: readonly string[]): string;
```

`solidStepKey` が混ぜるもの: 段の種類、数値パラメータ(距離・角度・許容量)、断面の全座標(mm、`toFixed(9)` で文字列化して丸めの揺れを消す)、向き、上流の鍵。**フィーチャーの名前・抑制・色は混ぜない**(形が変わらないため)。

**キャッシュの破棄.** 依頼に出てこない鍵は、**直近で使われなくなったものを最大 `SHAPE_CACHE_SPARE = 64` 件だけ残し**、それ以外は `delete()` して解放する(要件§10「結果キャッシュの LRU 破棄」)。64 件残すのは、Undo で1段戻したときに作り直さずに済ませるため。

**キャッシュの中身.** 鍵 → `{ shape, mesh, release }`。`release` は `maker.delete()` と `shape.delete()` の両方を行う(§1.2 の落とし穴)。

### 2.6 進捗とキャンセル(NFR-PF-4、§0.a-0.22)

- 進捗: 段を始める前に `onProgress({ done, total, label })` を呼ぶ。Worker は計算中でも**外向きの postMessage は出せる**ので、UI 側は計算中も更新を受け取れる。
- キャンセル: 段と段の間で `await yieldToMessages()`(= `new Promise<void>((resolve) => { setTimeout(resolve, 0); })`)を1回挟む。ここで Worker が受信待ちの `cancelSolidRecompute(generation)` を処理でき、`generation` が一致していれば以後の段を飛ばして `cancelled: true` で返す。
- **限界:** 1段の OCCT 演算そのものは途中で止められない。時間のかかるブーリアン1回を止めることはできない。この限界は注釈に書き、統括への報告にも明記する。

### 2.7 Undo / Redo(FR-505、NFR-UX-3、§0.a-0.13)

`packages/model/src/history/undoStack.ts`(新規)。文書は不変なので、スナップショットを積むだけで済む。

```ts
export const UNDO_LIMIT = 200;
export const UNDO_COALESCE_MS = 800;

export interface UndoStack<T> {
  readonly past: readonly T[];
  readonly present: T;
  readonly future: readonly T[];
  /** 直前の変更をまとめる鍵。null なら次の変更は必ず別の段になる。 */
  readonly coalesceKey: string | null;
  /** 直前の変更の時刻(ミリ秒)。 */
  readonly coalesceAt: number;
}

export interface PushUndoOptions {
  /** 同じ鍵の変更が UNDO_COALESCE_MS 以内に続いたら1段にまとめる。 */
  readonly coalesceKey?: string;
  /** 検査で時刻を固定するための口。既定は Date.now()。 */
  readonly now?: number;
}

export function createUndoStack<T>(present: T): UndoStack<T>;
export function pushUndo<T>(stack: UndoStack<T>, next: T, options?: PushUndoOptions): UndoStack<T>;
export function undo<T>(stack: UndoStack<T>): UndoStack<T>;
export function redo<T>(stack: UndoStack<T>): UndoStack<T>;
export function canUndo<T>(stack: UndoStack<T>): boolean;
export function canRedo<T>(stack: UndoStack<T>): boolean;
```

- `pushUndo` は `next === stack.present` なら何もしない(同じ文書を積まない)。
- 新しい変更を積むと `future` は空になる。
- `past` が `UNDO_LIMIT` を超えたら**古い方から捨てる**。
- 鍵の例: 式の書き換えは `` `field:${featureId}:${fieldKey}` ``、要素の追加は鍵なし(必ず別の段)。

### 2.9 自動保存とクラッシュ復元(FR-805、NFR-RE-2、§0.a-0.11)

- 置き場: IndexedDB のデータベース `pointercad`、オブジェクトストア `autosave`、鍵 `current` 固定の1件。
- 中身: `{ savedAt: string(ISO8601), name: string, json: string }`。`json` は §2.8 の `document.json` そのもの(ZIP にしない。復元に thumbnail は要らない)。
- 書く条件: `AUTO_SAVE_INTERVAL_MS = 300_000`(5分)ごと、かつ**前回の自動保存より後に文書が変わっているとき**だけ。
- 起動時: 控えがあれば復元の案内を出す。「復元」で読み込み、「破棄」で消す。**手動で保存に成功したら控えを消す**(残しておくと次の起動で古い方を勧めてしまう)。
- 検査: 判定は純関数 `shouldAutoSave(now, lastSavedAt, changedAt)` にして Node で検査する。IndexedDB そのものは E2E(タスク27)で確かめる。
