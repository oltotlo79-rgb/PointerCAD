## 2. 技術方式

### 2.1 実行境界と追加依存の根拠

[QuickJS公式文書](https://bellard.org/quickjs/quickjs.pdf)にはメモリ・stack・割込みの制御APIがある。候補wrapperの [quickjs-emscripten公式リポジトリ](https://github.com/justjake/quickjs-emscripten)にも `setMemoryLimit / setMaxStackSize / setInterruptHandler` の例を確認した（2026-09-10）。これは現在の本アプリに導入した検証結果ではない。候補の正確な版とWASM構成はタスク1で固定する。

実行ごとにVM contextを作り、host bindingはJSON相当の値と不透明IDだけ。`fetch/XMLHttpRequest/WebSocket/importScripts/Worker/DOM/Electron/require`を公開しない。ホストのFunction/オブジェクト参照がprototype経由で漏れないよう値をコピーする。VM内のeval/FunctionをJavaScriptとして許す場合もVM外へ脱出できないことを検査する。static/dynamic importは登録済みローカルモジュールの固定表だけで解決し、URL、絶対パス、`..`、外部パッケージ取得を拒否する。

### 2.2 型付きAPIと取引

`cad.document.read()`は読み取り専用snapshot、`cad.parameters.set(name, source)`、`cad.sketch.point/line`、`cad.solid.box/extrude`等は既存の型付きコマンドを発行する。式を数値へ事前に丸めずsourceとして渡せる。戻り値IDは当該実行の名前空間に閉じ、順序・存在・文書所有者・引数・資源量をhostでも再検証する。

状態遷移は `idle → running → validating → evaluating → committing → succeeded`。どこからでも取消/失敗へ移行でき、committingは文書ID・世代照合後の同期1回。実行中に利用者が文書を編集した場合は旧snapshotへの結果を適用せず、再実行を案内する。一時文書のカーネルcacheは独立ownerで管理し、成功で必要なものだけ譲渡、失敗/中止で回収する。途中のコマンドが成功しても実文書へ小分けにcommitしない。

### 2.3 実行上限

| 制約 | 採用値 | 判定と根拠 |
|---|---|---|
| script source | 1MiB | 通常の自動作図を超える入力を読込前に制限。UTF-8バイトで判定 |
| VM heap / stack | 64MiB / 128KiB | CAD/WASM本体とは別枠。実バイナリで停止とcatch後の失敗保持を検証 |
| JS経過時間 | 5秒 | 無限ループを止める実行予算。CAD呼出し待ちを含めた全体は別予算 |
| 実行全体 | 30秒 | CAD待ち/Promise待ちでも無期限に走らせない。単一典型CAD操作500msの要件は別途維持 |
| CAD命令数 / serialized命令列 | 1000 / 8MiB | 200フィーチャー規模の通常利用を対象にhost側でも検証 |
| console | 1000行・合計1MiB | 巨大文字列でUI/保存を圧迫しない |

上限到達は行番号付きエラーとし、文書差分0、Undo増分0。割込みコール数をCPU命令数と偽って報告しない。厳密な命令数の制限口がなければ、時間＋VMメモリ＋host命令数の契約を明記する。利用者の中止からUIの停止表示まで200ms以内を目標、カーネル内の中断不能区間は既存のキャンセル契約に従い、遅れた結果を絶対に適用しない。

### 2.4 決定性と保存

scriptId、名前、図柄、API版、source、同梱するローカルmoduleのsourceとhashを保存する。VMのbytecodeや評価済みキャッシュは保存しない。文書内に含まれるscriptも開くだけでは実行しない。道具登録は端末の一覧、生成したCAD履歴は文書の内容に分け、書き出し/読込時に利用者が対象を選べるようにする。

seed付きの乱数と実行snapshot時刻を入力に持ち、同じ入力の再実行は同じコマンド列となる。実世界時刻は明示的な入力値として渡す。実行ログにseed/API版/source hashを記録し、文書やソースを外部へ送らない。独自コード挿入で行番号をずらさず、ファイル名・行・列とローカルmodule名を保つ。

### 2.5 操作

既存プロパティ領域でsourceを編集し、実行/中止、エラー行への移動、例を開く、道具登録/編集/削除を行う。図柄は内蔵アイコンまたは検証したローカル画像。HTML/SVG scriptや外部URLを生のボタン内容として描画しない。名前と図柄の登録だけで自動実行しない。P12のショートカット/放射メニューは同じcommandIdを参照し、削除時の孤立した割当を説明する。

## 4. 共通の作業規約

- 最新の利用者指示により、実装・調査・資料作成は本エージェントが直接行う。**サブエージェントは使用しない**。旧計画のモデル名や委譲表を適用しない。
- 文書変更は不可変の定義に適用し、確定1操作をUndo 1回で戻す。一時プレビュー、検索、カメラ移動は文書に保存しない。端末設定は文書のUndoと分け、取消・既定値復元を備える。
- 式は文字列で保存し、任意精度で評価してカーネル境界でdoubleへ変換する。幾何許容誤差はmmと明示した値で判定する。UIからカーネルを直接呼ばない。
- 新規・切替・閉じる・保存先変更と非同期処理の競合では、文書IDと世代を照合し、旧結果で新文書や保存済み状態を更新しない。失敗時に唯一の控えを消さない。
- UIの追加には既存5区画、その場の入力、先選択/後選択、Enter/Esc、空状態、理由付きエラー、F1、ツールチップ、ステータス、翻訳キーを揃える。ヘルプ本文と説明書の章は同じMarkdownから供給する。
- 診断と必須ゲートを混同しない。検査は `scripts/check.ps1` のみを入口とし、検査中にソース・文書・indexを変更しない。未実在のテストを指定して「成功」と扱わない。
- コミットは§タスク一覧の**原計画IDを10件以上**、機能として区切りのよい範囲でまとめ、mainへ着地させる。ファイル数、検査数、不具合修正数を追加タスクに数えない。
- 完了は実装・保存・Undo・画面/出力・ヘルプ・必要な検査の全成立後。報告記録に成果物、残件、完成度、コミットまであと何分かの見積もりと根拠を書く。
