## 2. 各タスク

### R-1: 保存先を文書と一緒に確定・解除する

- **現状(根拠の行):** `packages/ui/src/file/partFile.ts:298-304` は新規作成時に文書とfileStateをリセットするがgatewayの保存先を解除しない。`:366-369` は `hasSaveTarget()` を保存先判定に使う。`packages/ui/src/file/fileGateway.ts:718-723` と `apps/desktop/src/main/pcadDialogs.ts:352-358` は、`partFile.ts:325-328` の構文検証より先に選択先を記憶する。
- **問題:** Aを開く→新規B→Ctrl+SでAを上書きし得る。A表示中に壊れたBをopen→拒否→Ctrl+SではAをBへ書き得る。Web/Electron共通の文書寿命の不具合である。
- **具体策:** `FileGateway` に保存先の解除と選択後の確定/破棄を追加する。openは一時的な不透明tokenを返し、`readPartDocument`成功と文書適用後にだけ確定する。新規・復元・種別変更では解除する。Electronはmainにtoken→pathを保持し、rendererへ実パスを出さない。
- **合格条件:** 「Aを開く→新規B→保存」はsaveAsになる。「A表示→壊れたBを選択→読込拒否→保存」はBへ書かない。open取消は現在の正常な保存先を保持する。Web/Electron双方で単体検査を固定する。
- **変えないもの:** パス非公開、1窓1文書、読込成功後に現在文書を切り替える契約。
- **関係する過去の失敗:** rules/06 §10.17。頁の寿命で生きる入れ物に文書寿命の状態を残さない。

### R-2: 自動保存の失敗を成功扱いしない・復元できない控えを残す

- **現状(根拠の行):** `packages/io/src/autoSave.ts:159-193` はrequest successだけを待ちerrorをnullへ変換、`:226-229` はnullを無視して成功完了、`:356-364` はZIP化後のwrite成功でlastSavedDocumentを更新する。`packages/ui/src/file/attachAutoSave.ts:217-221` は読めない控えを直ちにdiscardする。
- **問題:** 容量不足・DB不在・transaction abortが利用者にも再試行にも伝わらず、新schemaの控えを旧アプリが削除し得る。ZIP化の同期例外もwriteのcatch外である。
- **具体策:** `MinimalIDBTransaction` にcomplete/abort/errorを含め、transaction completeだけを成功とする。ZIP化も同じtry/catchへ入れ、失敗時はdirtyを保ち再試行する。読めない控えは残して理由と書出し手段を示し、削除は明示操作だけにする。durability指定の可否は別に実測する。
- **合格条件:** request成功後のtransaction abortがResult失敗になる。ZIP同期例外でもdirtyと控えが残る。未来版・破損控えは自動削除されず、書出しまたは明示削除を選べる。
- **変えないもの:** 操作を止めずに警告する方針。request成功とOS停電時の耐久性を同一視しない。
- **関係する過去の失敗:** rules/06 §10.19。「未対応」と「まだ完了していない」を分け、異なる失敗を成功へ畳まない。

### R-3: Booleanを非破壊モードで始め例外経路も解放する

- **現状(根拠の行):** `packages/kernel/src/occt/booleanOp.ts:57-63,79-149` は入力2形状を取るconstructorを使う。HasErrors/IsDone、solid、体積、妥当性を確認するが、後段の `Shape()`・測定・妥当性検査が例外になった経路を明示的不成立と同じ解放範囲で覆わない。
- **問題:** Booleanが下位形状の許容値・pcurveを更新してキャッシュ入力へ伝播する可能性があり、OCCT例外時に所有物も漏れ得る。rules/06 §10.16の再発余地である。
- **具体策:** 空builderを作り、`SetArguments` / `SetTools`、`SetNonDestructive(true)` を設定してから `Build` する。`Fuse_3/Cut_3/Common_3(target,tool,range)` の計算後にフラグを立てない。固定WASMで不可なら `BRepBuilderAPI_Copy_2(shape,true,false)` で入力を隔離する。`createAllocations`で全例外を覆い、返却形状へ必要な所有だけを移す。共通部分専用処理にも適用する。
- **合格条件:** 固定WASM上の正確なoverloadを実証する。成功・空結果・Build失敗・`Shape()`以降の例外で確保/解放数が一致し、失敗後の貸した入力を別のBoolean/測定で再利用できる。
- **変えないもの:** mm/rad、空結果と演算失敗の区別、入力形状を所有しない契約、既存の理由付き失敗。
- **関係する過去の失敗:** rules/06 §10.13(new/Handle/getの所有権)と§10.16(借用した形の変異)。

### R-4: 縫合で最初の殻だけを採らない・許容誤差を用途別の定数にする

- **現状(根拠の行):** `packages/kernel/src/occt/sewSolid.ts:106-189` は自由辺数を確認後、`findShell` が返す1 shellだけからsolidを作る。P5 §2.16のThruSectionsは `pres3d=1e-6`、要件の幾何許容は `1e-7 mm`。
- **問題:** 離れた2つの閉殻は自由辺0でも成立し、最初の殻だけ返すと材料が黙って消える。幾何一致・縫合修復幅・近似偏差・表示粗さを同じ「精度」にすると要件を誤判定する。
- **具体策:** 全shellを列挙し、「1つの閉じた外殻」の仕様なら複数殻を理由付きで断る。空洞殻を認める場合は包含・向き確認とsolidへの追加を別タスクにする。`packages/kernel/src/occt/tolerances.ts` に用途別の定数と単位を置き、finite・正・文書スケール上限を検証する。`Precision::Confusion` / `Angular` と操作別近似精度を分け、固定WASM値を記録する。
- **合格条件:** 1閉殻は成功、離れた2閉殻は黙って片方を返さず構造化失敗、自由辺ありは既存どおり失敗。各許容値は用途名・単位・入力範囲を持つ。
- **変えないもの:** 自動で大きなfuzzy toleranceへ広げない。表示三角形の偏差をB-rep幾何許容に読み替えない。
- **関係する過去の失敗:** rules/06 §10.19。「見つかった1つ」を全体の成功と扱わず、欠落理由を区別する。

### R-5: プリント点検と着色するメッシュの同一性を保証する

- **現状(根拠の行):** `packages/kernel/src/worker/recomputeSolids.ts:93-99,170-180` はばね・スイープ・実体ねじを0.15mm/0.7radでmesh化する一方、`packages/model/src/kernelBridge.ts:973-975,1116-1122` の `DISPLAY_MESH_QUALITY` は一般既定値。`packages/kernel/src/worker/kernelApi.ts:757-768` は別meshで点検し、`packages/ui/src/solid/printabilityColors.ts:108-118` は総三角形数の範囲だけで同じ番号へ着色する。
- **問題:** 掃引体では表示meshと点検meshの品質が異なる。点検側の枚数が多ければ範囲検査を通って別三角形へ赤・橙を塗り得る。別の再mesh化では同設定でも番号同一を保証できない。
- **具体策:** Worker cacheの実際の表示meshを点検へ渡し、結果へ `bodyKey + meshRevision + triangleCount` を添える。精密な別meshを点検する方式なら、その結果mesh自体をoverlay表示して元meshの番号へ塗らない。`printabilityCovers` は境界検査として残す。
- **合格条件:** 通常形・ばね・スイープ・実体ねじで3識別子が一致するときだけ着色する。不一致は理由付きで着色せず、別mesh方式ではoverlayのtriangle IDだけを使う。
- **変えないもの:** 粗い表示品質を全体的に細かくしない。三角形番号はmeshローカルIDという契約。
- **関係する過去の失敗:** rules/06 §10.17。寿命・名前空間の違う覚え書きをIDだけで使い回さない。

### R-6: メッシュ化の失敗契約を明示する

- **現状(根拠の行):** `packages/kernel/src/occt/tessellate.ts:350-417` は `BRepMesh_IncrementalMesh_2(shape,linear,false,angular,false)`、借用triangulation、Location変換、面方向の巻き順を扱うが、`:394` はtriangulation欠落を飛ばす。`packages/kernel/src/occt/exportMesh.ts:147-158` は位相を複製して再分割する。
- **問題:** 非退化面のtriangulationが欠けても、描画やSTL等が欠けた出力を成功として返し得る。mesherの状態が契約に出ていない。
- **具体策:** `IsDone()` / `GetStatusFlags()` が固定バインディングで使えるか実証する。非退化面にtriangulationが無い場合、描画は欠落を構造化警告、STL等の完全出力は構造化失敗にする。表示とexportで共通の状態型を使う。
- **合格条件:** 成功、mesher失敗、非退化面欠落、退化面欠落を別の結果にする。STL等は欠落時に成功バイト列を返さず、描画側の部分表示には対象faceと理由が残る。
- **変えないもの:** 絶対偏差、単一スレッド、Location変換、面方向の巻き順。剛体配置は深いcopyに変えない。
- **関係する過去の失敗:** rules/06 §10.13。新OCCT APIは型だけでなく実在・返却所有権を実証する。

### R-7: 参照・投影の再計算を依存順の収束へ変える

- **現状(根拠の行):** `packages/model/src/part/recomputePart.ts:458-475` はsolid作成後に参照と投影を更新し、必要ならsolidをもう1回だけ作る。2巡目後の参照更新・投影取得はない。`recomputePart.test.ts:1561-1788` は主に1段の依存を扱う。
- **問題:** cold cacheで `solid A→投影→solid B→Bの投影→solid C` と連鎖すると、Bは2巡目で初めてでき、C用投影の巡回がない。保存再開時だけ未解決になる恐れがある。
- **具体策:** 未解決要求を依存順に進めるschedulerへ変える。暫定の巡回方式なら参照/投影キー集合が新しく解決された間だけ続け、上限は文書の依存段数。同じ未解決集合なら対象ID付き診断で停止する。各巡回でgenerationと取消を確認し、最後の結果だけ適用する。
- **合格条件:** 上の3段連鎖がcold/warm cacheで同じ形・エラーになる。循環は固定50巡で隠さず停止理由とIDを返す。古いgenerationの結果を適用しない。
- **変えないもの:** cacheは結果を変えない最適化。PartDocument、投影定義、取消後に最後の成功表示を残す方針。
- **関係する過去の失敗:** rules/06 §10.17(頁寿命cache)と§10.19(計算待ちと未対応の区別)。

### R-8: パラメータ間の任意精度と単位の種類を分けて扱う

- **現状(根拠の行):** `packages/expression/src/evaluate.ts:17-28` は40桁Decimalだが、`:118-132` は変数値をnumberから再生成する。`packages/model/src/parameters/parameterTable.ts:146-155` は式ごとの結果をnumberのMapへ入れる。長さ単位は `packages/expression/src/lengthUnits.ts:31-43` が25.4を文字列定義し、`packages/model/src/units/length.ts:189-199` が表示入力を式へ戻す。
- **問題:** 式内が40桁でもパラメータ境界ごとにdoubleへ丸め、「kernel直前だけ丸める」契約にならない。P11bのN・MPa・N·mmを長さの単位flagへ足すと次元が崩れる。
- **具体策:** expressionへDecimal値または精度を失わない10進文字列を受ける評価contextを追加し、parameter DAG中は保持する。model公開値・OCCT入力の境界でnumberへ変換する。P11bは `QuantityKind`(length/force/stress/torque/angle等)とSI換算係数を計算panel境界に置く。
- **合格条件:** `a=1/7; b=7*a-1` がパラメータ境界のdouble丸めを持ち込まない。25.4の厳密定義、循環検出、変数名書換え、mm/inの既存入出力が全て維持される。quantity kindの不一致を理由付きで断る。
- **変えないもの:** 内部mm/rad、式文字列の保存、既存mm/in入力規則を全面改訂しない、kernelへはdouble。
- **関係する過去の失敗:** rules/04の数値精度規律。表示単位と計算単位の責務を混ぜない。

### R-9: ZIP展開前の上限と数値配列の検証を追加する

- **現状(根拠の行):** `packages/io/src/pcad/pcadFile.ts:408,753` と `packages/io/src/threemf/readThreeMf.ts:775-777,838-852` は `unzipSync` 後に検査する。`pcadFile.ts:235-258` はmeshのbyte長だけを確認し、positions/normalsのfiniteと `indices < vertexCount` を確認しない。`packages/io/src/dxf/readDxf.ts:161-164,801-803,875` は深さ8・実体数上限を既に持つ。
- **問題:** 小さいZIPから巨大展開してメモリを消費できる。正しい長さのNaN/Infinity/不正indexが描画・計測へ届き得る。3MFの少数objectを大量build itemで複製する確保も先行し得る。
- **具体策:** `limits.ts` と `pcad/readArchive.ts` へ圧縮入力、entry数、各展開量、累積展開量、参照展開後個数を一元化する。中央directory事前検査だけでなく実inflate出力量を数えて打ち切る。許可entryだけを展開し、重複名・不正pathを拒否する。meshは `24×vertexCount + 12×triangleCount` を確保前に確認し、全値finite、全index範囲、法線長を検証する。DXFはtext/tag総量もparse前に制限する。
- **合格条件:** zip bomb、虚偽declared size、entry過多、重複名、path traversal、NaN/Infinity、範囲外index、大量build itemを全て確保前または上限到達時に理由付きで拒否する。既存のdepth/entity制限は維持する。
- **変えないもの:** 正常な旧版pcad/pcada/3MF/DXF、未知の新schemaを理由付きで拒否する方針。具体byte上限は50部品fixtureとJS/WASM予算の実測後に統括が確定する。

### R-10: Electronの送信元検証・遷移制限・原子的保存を追加する

### R-12: Pagesの25MiB制限に対するWASM配信を先行実証する

- **現状(根拠の行):** `packages/kernel/src/occt/loadOcct.browser.ts:1-2,47-59` はfull.js/full.wasmのURLを直接使い、P0計画はWASM 50.3MBを記録する。`apps/web/vite.config.ts` は資産として扱い、`apps/web/public/_headers` はCOOP/COEP/CORPを設定する。
- **問題:** Cloudflare Pagesの単一静的asset上限は25MiBで、通常のContent-Encoding gzipだけでは50MB fileのupload制限を解消しない。現状のまま本番公開可能とは証明できない。
- **具体策:** 方式Aを先に実測する。候補①build時圧縮した25MiB未満assetを明示展開して同梱glueへbytesを渡す、②各25MiB未満のchunk＋manifest/hashを結合する。候補③は同一管理下R2等への分離で、Aが成立しない/不利と判明した後の利用者判断とする。自動Content-Encoding展開と明示展開を二重にしない。chunk方式は追加memory、R2方式はCORS/CORP・運用を測る。
- **合格条件:** 方式Aについて実圧縮size、各asset size、cold/warm load、復元中peak memory、固定browser、WASM MIME、hash不一致、旧asset保持を数値で報告する。全chunkが25MiB未満で、組立後hashが元WASMと一致し、OCCTの解析形が動く。
- **変えないもの:** model dataを送信しない、同梱OCCT版、COOP/COEP、利用者判断前にR2運用を決めない。対応browser・offline更新はP13計画へ渡す。
- **関係する過去の失敗:** rules/06 §10.14・§10.18。実行機依存の推測でなく固定条件の実測を取り、既定の圧縮/並列へ依存しない。
